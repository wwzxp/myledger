# docs/architecture/

## 职责

- 描述系统的目标架构与已实现架构，二者必须显式区分。
- 用 mermaid 表达分层、数据流、模块边界；图与表格互为补充，不重复叙述。

## 不负责

- 为什么这样选（在 `docs/adr/`）。
- 接口签名与实现细节（在各模块 `README.md`）。
- 产品需求（在 `docs/specs/`）。

## 对外接口

| 文件 | 内容 |
|---|---|
| `架构.md` | 目标分层图、导入时序图、模块边界表、关键不变量、尚未确定项 |

## 依赖

- 模块边界变化时同步 `INDEX.md` 与受影响模块的 README。
- 架构级变化需同时新增 ADR。

## 已知限制

- 当前为**目标架构**，代码尚未实现；实现落地时必须更新状态标注，避免把计划写成现状。
