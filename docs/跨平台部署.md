# 跨平台部署（Linux / macOS）

本应用除 web 面板外没有平台相关代码：HTTP 用标准库 `ThreadingHTTPServer`，
数据库是 SQLite，路径全部走 `pathlib`，依赖（openpyxl / pyzipper /
cryptography / pdfplumber）在三大平台都有 wheel。

## 零、最简单的方式：下载单个可执行文件

每个 Release 提供三个平台的单文件二进制，**不需要安装 Python**：

| 平台 | 文件 |
|---|---|
| Linux x86_64 | `myledger-linux-x86_64` |
| macOS Apple Silicon | `myledger-macos-arm64` |
| Windows x86_64 | `myledger-windows-x86_64.exe` |

```sh
chmod +x myledger-linux-x86_64
sudo install -m 755 myledger-linux-x86_64 /usr/local/bin/myledger
myledger --version
```

之后按「四、开机自启」配 systemd 即可，运行方式与 venv 安装完全相同：
`ExecStart=/usr/local/bin/myledger --config /etc/myledger/myledger.toml dashboard --host 127.0.0.1 --port 8765`。

**注意**：PyInstaller 不能交叉编译，所以每个平台的二进制由对应 runner 各自构建
（见 `.github/workflows/build.yml`）。Intel Mac 目前未提供，需要时用 `macos-13` 补一个矩阵项。

### 打包态的限制

单文件二进制里**没有 `.py` 源文件**（只有编译进归档的字节码）。
因此任何「按文件路径动态加载模块」的写法在打包后都会失败——
本项目踩过一次：`app/importers.py` 曾用 `spec_from_file_location` 加载
`bookkeeping.py`，结果导入账单一律报
`No such file or directory: _MEI.../app/bookkeeping.py`。

写这类代码时：先判断源文件是否存在，不存在就走包内常规 import；
新增被动态加载的模块要加进 `scripts/build-binary.py` 的 `hiddenimports`。

### glibc 兼容性

Linux 二进制只能在 **glibc ≥ 构建机版本**的系统上运行。CI 用 `ubuntu-22.04`
（glibc 2.35）构建，因此：

| 目标发行版 | glibc | 可用 |
|---|---|---|
| Ubuntu 22.04 / 24.04 | 2.35 / 2.39 | ✅ |
| Debian 12 | 2.36 | ✅ |
| Debian 11 | 2.31 | ❌ 用源码方式装 |
| CentOS 7 | 2.17 | ❌ 用源码方式装 |

**不要改回 `ubuntu-latest`**：它已经是 24.04（glibc 2.39）打出的包在老服务器上会
`libm.so.6: version 'GLIBC_2.38' not found`。CI 里有一道校验会拦住这种回退。

## 一、依赖与安装（源码方式）

要求 Python 3.11+。

```sh
# 建议装在独立 venv，不污染系统 Python
python3 -m venv ~/.venvs/myledger
~/.venvs/myledger/bin/pip install --upgrade pip
~/.venvs/myledger/bin/pip install /path/to/myledger
```

装完入口在 `~/.venvs/myledger/bin/myledger`。macOS 与 Linux 路径规则一致。

> 用 `pip install <源码目录>` 会复制一份到 `site-packages`。
> 改完源码必须重新执行这条命令，否则跑的还是旧副本（Windows 部署上踩过这个坑）。

## 二、配置

配置只有一种来源：**TOML 文件**，不读环境变量。

查找顺序：`--config <路径>` → 当前目录 `myledger.toml` →
`~/.config/myledger/config.toml` → 内置默认值。

最小配置：

```toml
[database]
path = "/home/you/myledger-data/ledger.db"

[backup]
enabled = true
directory = "/home/you/myledger-data/backups"
keep = 14
interval_minutes = 60

[mail]
# 加密邮箱授权码用的主密钥；一旦丢失，已保存的授权码无法解密
secret_key = "换成一串随机字符"
```

数据库目录会自动创建。**该目录属于敏感数据**（含姓名、账户、流水号），
建议 `chmod 700`。

## 三、运行

```sh
~/.venvs/myledger/bin/myledger --config ~/myledger-data/myledger.toml
```

默认监听 `127.0.0.1:8765`。首次启动若库里没有用户，会在日志打印管理员初始密码。

### 只允许本机访问（默认）

```sh
myledger --host 127.0.0.1 --port 8765
```

### 通过反向代理对外提供服务

应用自身不处理 TLS。公网暴露请放在 nginx / Caddy / Cloudflare Tunnel 之后，
并让代理带上 `X-Forwarded-Proto: https`——应用据此决定会话 cookie 是否加
`Secure`（明文 HTTP 下加了 `Secure`，浏览器会拒绝发送 cookie，表现为登录后立刻 401）。

nginx 片段：

```nginx
location / {
    proxy_pass http://127.0.0.1:8765;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 300s;   # 导入大账本时单次请求可能较久
}
```

## 四、开机自启

### systemd（Linux）

`/etc/systemd/system/myledger.service`：

```ini
[Unit]
Description=AI Ledger
After=network.target

[Service]
Type=simple
User=ledger
WorkingDirectory=/home/ledger
ExecStart=/home/ledger/.venvs/myledger/bin/myledger --config /home/ledger/myledger.toml
Restart=always
RestartSec=3
# 数据库只对本进程可读
UMask=0077

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now myledger
sudo journalctl -u myledger -f
```

`UMask=0077` 让建出来的数据库与备份默认只有属主可读，这一点比在代码里
逐个 `chmod` 更可靠。

### launchd（macOS）

`~/Library/LaunchAgents/dev.ailedger.plist`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>dev.ailedger</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/you/.venvs/myledger/bin/myledger</string>
    <string>--config</string>
    <string>/Users/you/myledger-data/myledger.toml</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/Users/you/myledger-data/out.log</string>
  <key>StandardErrorPath</key><string>/Users/you/myledger-data/err.log</string>
</dict></plist>
```

```sh
launchctl load ~/Library/LaunchAgents/dev.ailedger.plist
```

## 五、平台差异清单

| 项 | 影响 | 处理 |
|---|---|---|
| 配置文件位置 | Windows 与类 Unix 路径不同 | 代码统一用 `~/.config/myledger/config.toml`；Windows 也是这个路径 |
| 文件权限 | Linux/macOS 按 umask 生成，可能同机可读 | 用 systemd `UMask=0077` 或手动 `chmod 700` 数据目录 |
| 本地模型 | `llama-server` 需自行编译或下载对应平台二进制 | 不装也能用，未命中规则的条目留待人工确认 |
| 端口占用 | 默认 8765 | `--port` 覆盖 |
| 时区 | 账单时间按本地时区解析 | 服务器时区建议与账单一致（`timedatectl set-timezone Asia/Shanghai`） |

## 六、已知限制

- 不提供 Docker 镜像；上述 venv 安装已覆盖主要场景。
- 邮件收取依赖 IMAP（QQ 邮箱需授权码），与平台无关。
- 没有数据库迁移工具；跨大版本升级前先 `myledger backup`。
