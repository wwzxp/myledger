# 从录屏做出可播放的功能演示

> **本文档是给 AI 执行的任务说明，不是给人读的教程。**
> 按顺序做完 §0 到 §11，产出必须通过 §10 的验收命令。不要跳步，不要凭经验补全。

---

## 0. 任务契约（先读，这是验收标准）

### 0.0 你必须产出什么

在目标项目的 `demo/` 目录下，必须存在以下文件，缺一不可：

```text
demo/
  stage.js          舞台：缩放、播放、进度、切场景
  kit.js            积木：h()、cursor()、type()、ok()、group()
  demo.css          全部样式
  gsap.min.js       GSAP 3（本地文件，不用 CDN）
  scenes/
    index.js        导出 SCENES = { [key]: buildFn }
    <你的场景>.js    每个场景一个文件
  index.html        可独立打开的演示页
```

### 0.1 验收命令（必须全部通过才能算完成）

```bash
# 1 语法
node --check demo/stage.js
node --check demo/kit.js
for f in demo/scenes/*.js; do node --check "$f"; done

# 2 起服务
python -m http.server 8899 --bind 127.0.0.1

# 3 跑断言验收（脚本见 §10.5）
node verify.js --url http://127.0.0.1:8899/index.html --spec ./screens.json
```

**必须用断言脚本，不能「打印出来看看」**（脚本见 §10.5，文件在 `docs/reference/assets/verify.js`）：

```bash
node verify.js --url http://127.0.0.1:8899/index.html --spec ./screens.json
```

**判定标准，缺一不算完成**：

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 屏清单断言 | `screens.json` 里每屏的 `mustContain` 文案全在、`minStats` 全部达标 |
| 2 | 切页 | 不能连续 3 秒显示 2 页 |
| 3 | 光标 | 在画布内，且停过 ≥2 个不同位置（纯展示页用 `"cursor": false` 声明） |
| 4 | JS 错误 | `pageerror` 与 `console.error` 数量为 0（favicon 404 除外） |

**只看「能跑」不算通过。** 实测过：一个只画文字不画图标的实现，页面能正常切、光标正常动、
无 JS 错误，但 `iconLike = 0` —— 必须判不通过。

### 0.1.1 断言全绿 ≠ 做完了

**这是反直觉的一条，但实测过两次。**

`verify.js` 只能查四件事：文案在不在、元素数量够不够、有没有 JS 错误、光标动没动。

它**查不了**：

| 查不了 | 后果 |
|---|---|
| 图标画得像不像 | 用 `○` 代替微信图标，照样通过 |
| 卡内行距、对齐 | 行距差 6px，肉眼明显，断言无感 |
| 颜色准不准 | `#29ad66` 写成 `#2ea44f`，通过 |
| 字体粗细、圆角 | 全用默认值，通过 |

**实测**：一个零记忆 AI 首跑就 `verify` 退出码 0，
但把截图和基准帧并排一看，图标形状、卡内行距差很多。

**所以验收是两件事，并列，不能互相替代**：

```text
① verify 退出码 0        → 机器能判的部分
② 截图并排比对，差异表全 ✓ → 人（或你的视觉）能判的部分
```

**只做 ① 交付的是「结构对、样子不像」。**
**只做 ② 交付的是「样子像、结构漏」（前面验过：少 4 行肉眼没看出来）。**

两个都得做。

### 0.2 复刻录屏时，这些视觉元素一个都不能省

**这是最容易偷懒的地方。** 只画文字行 = 不合格。

| 元素 | 必须有 | 例子 | 注意 |
|---|---|---|---|
| 图标 | 每行左侧的彩色图形 | 黄色圆环 + 内部符号 | **可能是白底线条，不一定有底色** |
| 主标题 | 每行的主要文字 | `零钱` | |
| 副标题 | 小字，可选项 | `收益率0.85%` | **颜色要取色值**，实测是橙色不是灰色 |
| 右侧值 | 金额、状态，可选项 | `¥88.88` | |
| 尾部箭头 | 可点行的 `›` | `›` | **不是每行都有**，要逐行看 |
| 分组间隔 | 组与组之间的空白 | 9–10px 灰缝 | 可能是**浅灰细线**不是灰缝 |
| 导航栏三件套 | 左返回 / 中标题 / 右操作 | `‹` / `钱包` / `账单` | |

**判据（这条要真的执行，不是心里想一遍）**：

1. `read` 打开基准帧
2. `read` 打开你截的画布图
3. 逐项对：行数、每行元素、图标颜色、特殊元素
4. **信息量必须一致**。少一个副标题、少一个右侧金额，都算没复刻完

**注意**：只用眼睛「想象」两张图不算。必须调用 `read` 把两张 PNG 都打开过，
否则你不知道自己漏了什么。详见 §1.4。

### 0.2.1 时间成本（实测，务必先看）

**做一屏要多久**（本次实测数据）：

| 步骤 | 耗时 | 说明 |
|---|---|---|
| 切图（`frame-crop.py`） | **3 秒** | 10 行一次切完，含合成图 |
| 读图（逐张 / 3 行合成） | **1–3 分钟** | 一次一张，读完即写 |
| 写场景代码 | 5–10 分钟 | 骨架已给，主要是填内容 |
| 截图 + 比对 + 改 | 10–20 分钟 | 通常 2–7 轮 |
| **单屏合计** | **20–35 分钟** | 实测一次完整跑通约 35 分钟 |
| **10 屏合计** | **3–6 小时** | |

**对比：没有工具链时**（纯靠 AI 看图逐帧读）：单屏 24 分钟还没开始写代码。
`frame-crop.py` 把「数结构」从 20 分钟压到 **3 秒**。

**这是走完整流程的真实成本。** 想快，只有两个办法：

| 办法 | 代价 |
|---|---|
| 跳过像素校验，只读图 | 组数/行数会数错（实测三方结论全不一样） |
| 跳过读图，只跑断言 | 能跑但没复刻到位（实测 `iconLike` 通过但结构全错） |

**两个都跳 = 做出来的东西能跑，但和录屏没关系。**

**一个真实的卡死案例**（本次实测）：

一个零记忆 AI 拿到钱包页基准帧后，做了 24 分钟、151 次请求，**还没开始写代码**。
它把这张图里能数的都数对了：

```text
白卡 3 张：卡1 y=70–300（5 行）、卡2 y=311–356（1 行）、卡3 y=366–551（4 行）
合计 10 行
箭头：10 行全有（x≈300–305，颜色 rgb(180,180,180)）
有右侧金额：2 行（第 1、3 行）
橙色副标题：2 行（第 3、6 行）
```

但它卡在**认字**上：原图字高只有 11–13px，放大后中文仍是模糊块，
第 4/5/7/8 行中间几个字反复读不准，于是一直重读、不敢往下走。

**根因是文档缺退出口**：只给了「必须读图」和「数量要校验」，
没给「读不清时怎么办」。已补 §1.4.6 的退出口规则（见上）。

**这条教训比任何技术细节都重要**：流程里每个可能卡住的环节，
都必须写明「什么情况下允许放弃、放弃后怎么继续」。

**第二次实测（同一张新帧，补了上面的退出口之后）**：

仍卡住，但卡法变了——这次不切图了，改成用 `bash` 跑 Python + PIL 逐像素测量：
量字高、量行距、量分隔线颜色，量了 33 次请求、24 分钟，**又是 0 个代码文件**。

它自己的诊断很准：

> 我卡在「优先读数字，不敢写代码」，已经越过文档 §1.4.6 的退出线。
> **我在用 Python 逐像素验字高中**，这是 §0.2.1 明确点名的死法。

**教训**：只管「切图次数」的锚点没用，AI 会换一种测量方式绕开它。

**所以锚点必须是「任何拿数字的操作」**：

| 计数对象 | 包括 |
|---|---|
| 读图 | `read` 一张 png |
| 切图 | 生成任何新的裁剪文件 |
| **像素测量** | `bash` 里跑 PIL/numpy 算尺寸、颜色、字高、行距 |

三者合计超过 **行数 + 3** 就停，进入写代码。

### 0.3 执行顺序（不要跳）

```text
1  抽帧，用 read 看图选帧   → 产出：每屏一张有完整内容的基准帧
2  读基准帧，逐项记录       → 产出：screens.json（§10.6.2）+ 元素清单
                              ⏱ 上限 10 分钟，超了用已读内容先往下走
3  复制骨架代码             → 产出：stage.js / kit.js / demo.css
4  写第一个场景             → 产出：能跑起来的最小版本
                              ⏱ 到这一步必须已经存在可打开的 index.html
5  截自己的画布，再读一次图 → 产出：与基准帧的差异表（§10.5.0.4）
6  按差异表逐条修，重复 5   → 产出：差异表全 ✓
7  逐项核对光标             → 产出：[toAt] 日志全部命中
8  隐私脱敏                 → 产出：grep 结果为 0
9  跑断言验收               → 产出：verify.js 退出码 0
                              ⏱ 这一步不许省略，写完全部文件立刻跑
```

**第 9 步是最容易被跳过的**（实测两次都没跑到）。写完文件不等于做完，
必须起一个本地服务、打开、跑 `verify.js`。

**一次实测的反例**：一个 AI 写完了 7 个文件、结构内容都对，
但 `index.html` 里引用 `./gsap.min.js` 而文件在上一级目录，
运行时直接 `Cannot read properties of undefined (reading 'set')`，整屏渲染不出来。
**它没跑第 9 步，所以不知道。**

**第 9 步的最小动作**（复制即用）：

```bash
# 起服务（Windows）
Start-Process -FilePath "<venv>\Scripts\python.exe" `
  -ArgumentList "-m","http.server","8894","--bind","127.0.0.1" `
  -WorkingDirectory "<你的 demo 目录的上一级>" -WindowStyle Hidden

# 跑 verify
node verify.js --url http://127.0.0.1:8894/demo/index.html \
  --spec screens.json --seconds 3 \
  --puppeteer file:///E:/ai/tmp/ledger-mocks/node_modules/puppeteer-core/lib/puppeteer/puppeteer-core.js
```

**探路先确认三个路径都在**：`index.html`、`gsap.min.js`、`screens.json`。
`gsap.min.js` 必须在 `index.html` 的**同一目录**，否则 `<script src="./gsap.min.js">` 会 404。

**两条硬规矩**：

1. **第 1 步不许跳过。** 用 `read` 真的把帧看一遍，不能只看文件名挑帧。
   抽出的帧里有大量加载中/转场的废帧，不看图分不出来。
2. **第 5 到第 6 步必须循环到全 ✓。** 只截一次图不算做完。
   实测中「少画四行」「缺左侧竖条」这类差异，只有读图能发现，断言查不出来。

**一条时间闸门（新加，实测两次踩坑）**：

| 检查点 | 闸门 | 超了怎么办 |
|---|---|---|
| 进入第 3 步的时机 | 从开始读图算起 **≤ 10 分钟** | 立即停，按已读到的内容搭骨架 |
| 第 2 步的产出 | 允许不完整 | `screens.json` 只放已确认文案，其余用 `minStats` 兜底 |
| 测量操作总数 | ≤ 行数 + 3 | 计数口径见 §0.2.1（读图 + 切图 + 像素测量） |

**第 3 步之后不许再回头测量。** 唯一允许的「量」是第 5 步截自己的画布去比对，
那是**验证**不是**准备**——区别在于：验证会直接导致改代码，准备不会。

**判断「我是不是在准备而不是在验证」**：这次操作之后，
下一个动作是 `write`/`edit` 吗？不是，那你就在准备，该停了。

### 0.3.1 第三次实测：零记忆 AI 完整跑通，暴露 5 个真实 bug

第三次跑（本次）：给了「这是微信账单下载页」这样的**正常提示**，
不给项目记忆。结果：写了 7 个完整文件、结构内容全对，
但 verify 一开始报 9 项失败。逐个查清后发现，**其中 5 项是工具或文档的 bug，不是 AI 的错**。

| # | 现象 | 真实原因 | 修法 |
|---|---|---|---|
| 1 | `Cannot read properties of undefined (reading 'set')` | `gsap.min.js` 不在 `index.html` 同级目录 | 文档写明必须在同一目录 |
| 2 | 整屏「没等到标题」，但页面文字明明有 | `verify` 抓 scope 时选中了遮罩层 `d-scrim`，它 `textContent` 为空 | 改为选「文字最多」的可见层 |
| 3 | 同上，加了文字优选后仍失败 | 这一屏只有 `d-scrim` 满足「绝对定位+同尺寸」，其余层不满足 | 全部无文字时退回「排除遮罩类后文字最多的后代」 |
| 4 | `minCount` 里 `.d-*` 全是 0，但 DOM 里明明有 | `minCount` 用的是**旧的 scope 解析**，没跟着改 | 抽成 `window.__resolveScope()`，三处共用 |
| 5 | `.d-pill.is-on` 计数 0，胶囊高亮完全不生效 | `h("div","pill is-on")` → `class="d-pill d-is-on"`，CSS 要的是 `.d-pill.is-on` | 加 `flag(el,"on")` 辅助函数，文档写明前缀机制 |

**后 4 条的共同点**：都是「同一份逻辑抄了两遍，改一处忘另一处」。
现在 `verify.js` 里只有**一个** scope 解析函数，屏检测 / `minCount` / 自定义断言全用它。

**第 5 条最隐蔽**：不报错，只是高亮不显示。人眼比对也容易漏（绿色胶囊变成灰的，
但框架在、文字在，看着「差不多」）。

### 0.3.2 像素口径 ≠ DOM 口径

`frame-crop.py` 的 `rows` 数的是**暗区文字块**；
`verify.js` 的 `minStats.rows` 数的是**渲染后的行元素**。实测同一屏：

| 来源 | rows |
|---|---|
| `frame-crop.py`（有白卡时） | 10 |
| `frame-crop.py`（无白卡，fallback） | 4 |
| `__collectStats`（DOM） | 10 |

**所以 `minStats` 不能拿像素数直接当门槛。** 现在 `--emit-spec` 的做法：

- 识别出白卡 → 用像素值 × 0.6 当下限
- **没识别出白卡 → 直接不给 `minStats`**，并在 `_comment` 里标「低置信，请自己填」

不是所有界面都有白卡。表单页、全屏列表、深色背景都可能没有，
这时工具会明确说「我不知道」，而不是编一个数字出来。

### 0.3.3 `--emit-spec`：别再手写 thresholds

```bash
python frame-crop.py frame.png --outdir crops --emit-spec screens.json
```

生成的是骨架，三处 `TODO` 要手填：`name`、`expectText`、`mustContain`。
`minStats` 能自动填就自动填，填不了就留空——**留空比填错好**。

手写 `minStats` 的典型事故（本次实测）：
AI 凭感觉写了 `rows: 11 / mutedText: 6 / clickables: 3`，
实际 DOM 是 `10 / 5 / 2`，于是永远差一项，卡在「不通过」出不来。
**这三个数字没有任何工具能提前告诉你，纯属猜。猜错就是白跑。**

### 0.3.4 三种布局，工具能力不同

`frame-crop.py` 的 `rows` 按**横向暗区**计数，所以不同布局的可靠性差很多：

| 布局 | 例子 | `rows` 含义 | 可信度 |
|---|---|---|---|
| **列表页** | 账单流水、聊天列表 | 一条记录 = 一行 | **高**，与 DOM 基本 1:1 |
| **表单页** | 设置项、下载账单 | 一个字段 = 一行 | 中，无白卡时降级 |
| **图标宫格** | 微信「服务」页 | **一排图标 = 一行** | **低**，一行里可能有 4 个格 |

**宫格页要自己数格子，不要用 `rows` 当格子数。**

实测微信「服务」页：`frame-crop.py` 报 `4 张卡 / 12 行 / 3 种颜色`，
实际是 6 个分组、约 20 个图标格、颜色超过 8 种。
工具没错——它数的是「横向暗区」，一排四个图标确实只算一行——
但这个数字对宫格布局没有意义。

**宫格页怎么写 `minStats`**：

```json
"minCount": {
  ".d-cell": 20,
  ".d-cell .d-icon": 20
}
```

用 `minCount` 数格子，别用 `minStats.rows`。宫格的行数取决于屏幕宽度能排几个。

**判断你的页面属于哪一类**：基准帧里「同一水平线上有几个可点的方块」。
一个 → 列表页；零个（只有文字）→ 表单页；两个以上 → 宫格页。

### 0.3.5 第四次实测：零提示、宫格布局，跑通了

前两次零提示盲测都卡在「读」上出不来（14 分钟 / 24 分钟，0 个代码文件）。
按 §0.2.1 的计数口径（读图 + 切图 + 像素测量）和 §0.3 的时间闸门修完后，第四次：

| 指标 | 第一次 | 第二次 | 第四次 |
|---|---|---|---|
| 提示 | 零 | 零 | **零** |
| 布局 | 列表页 | 表单页 | **图标宫格** |
| 切图次数 | 15+ | 2 | **1** |
| 写出的文件 | 0 | 0（叫停后补写完 7 个） | **7 个 + screens.json** |
| 走到第 9 步 | 否 | 否 | **是** |
| `verify` | 未跑 | 不通过 | **退出码 0** |

**它自己识别出了「微信服务页」**，没有被告知。做出来的东西：
绿色主卡（收付款 / 钱包 ¥20.00）、4 个分组、18 个图标格、
颜色分类正确（蓝/黄/蓝/橙/青/红/橙…）。

**宫格布局下工具是低估的**：`frame-crop.py` 报 `4 卡 / 12 行 / 3 种颜色`，
它自己数出 `4 卡 / 18 格 / 41 个图标候选`。见 §0.3.4——宫格要用 `minCount` 数格子，
不能用 `rows`。

**关键变化**：闸门真的能拦住「无限读图」。
第一次是 126 次请求 0 产出，第四次是 51 次请求完整交付，
其中**读图只占前 16 次**，后面 35 次全在写代码和调 verify。

**但仍未解决的部分**：它最后多花了约 10 分钟在打磨细节（51 次请求时
还在跑 verify 迭代）。这个阶段没有闸门，也不该有——§0.3 第 5-6 步本来就要求循环到全 ✓。

### 0.3.6 第四次实测：六条卡点（零记忆 AI 自述）

跑通之后问了被测 AI「还有什么坑文档没写」，它的回答按价值排序：

**① `verify` 通过 ≠ 视觉对齐（最重要）**

它首跑就是退出码 0，但**截图并排一看**，图标形状、卡内行距都差很多。

> 「verify 通过 ≠ 视觉对齐，缺硬闸门。」

`verify.js` 只能查：文案在不在、元素数量够不够、有没有 JS 错误、光标动没动。
**查不了**：图标画得像不像、间距对不对、颜色准不准。

**所以第 9 步跑绿不算完，§0.3 的第 5–6 步（截图比对）照样必须做。**
这两件事是并列的，不是替代关系。

**② 端口残留会让验证打到别人的页面**

旧 `http.server` 占着端口时，新进程**静默绑定失败**，
`verify` 连到的是上一个 demo，表现为莫名 404 或验证到错误内容。

起服务前先确认端口空闲：

```powershell
# 看谁占着
Get-NetTCPConnection -LocalPort 8896 -State Listen -ErrorAction SilentlyContinue
# 杀掉
Stop-Process -Id <PID> -Force
```

或者干脆每次换一个没用的端口。

**③ `puppeteer-core` 单独调用必须传 `executablePath`**

`verify.js` 内部有 `findChrome()` 兜底，自己写截图脚本时没有，
直接照抄会报 `An executablePath or channel must be specified`。

```js
// verify.js 里
executablePath: arg("chrome", findChrome())
// 自己写脚本时至少写死一个
executablePath: 'C:/Program Files/Google/Chrome/Application/chrome.exe'
```

**④ `h()` 的 `d-` 前缀会导致 `minCount` 静默计 0**

`screens.json` 里写 `".card"` 而不是 `".d-card"`，不会报错，只是永远数到 0。
**看到 `minCount` 全是 0 时，第一件事是检查前缀。**

**⑤ 合成图（`groupNN.png`）会压扁行距，卡片边界只能看 `summary.json`**

想要精确的 `y` 边界，读 `summary.json` 里的 `cards[].y0/y1`，不要目测合成图。

**⑥ 宫格页的 `chevrons` 也是误报**

实测微信服务页 `frame-crop.py` 报「箭头 3 个」，实际这页一个 `›` 都没有。
`count_chevrons` 按「右侧浅灰细线、高 8–14px」找，
宫格里彩色图标的边缘也会命中。

**宫格页只信 `cards`（卡片边界对），`rows` 和 `chevrons` 都别用。**

### 0.4 禁止事项（出现即返工）

| 禁止 | 原因 |
|---|---|
| 凭记忆写界面，不看抽出的帧 | 一定会漏元素 |
| 在场景构建阶段计算光标坐标 | 那时页面还没切换，坐标必错 |
| 用 `left/top` 做位移动画 | 触发重排，且与 transform 缩放冲突 |
| 在页容器上写 `display: flex` | 隐藏不掉，页面会叠加 |
| 对 GSAP 的字符串位置做算术（`at + 0.18`） | 生成非法值，回调永不执行 |
| 用 `!important` 压样式冲突 | 掩盖问题，后续无法维护 |
| 照抄录屏里的真实姓名/金额/卡号/邮箱 | 隐私事故 |
| 只画文字不画图标、副标题、右侧值 | 信息量不足，等于没复刻 |

## 1. 背景（可略读）

### 1.1 最终产物长这样

```text
┌──────────────┬─────────────────────────────────┐
│ 功能清单      │  固定尺寸的演示画布              │
│              │  ┌───────────────────────┐      │
│ ▸ 微信导出    │  │  手机外壳              │      │
│   支付宝导出  │  │  一屏一屏切换           │      │
│ ▸ 邮箱导入    │  │  光标移动、点击、打字    │      │
│              │  └───────────────────────┘      │
│              │  ▬▬▬▬▬▬▬▬▬▬▬  进度条            │
└──────────────┴─────────────────────────────────┘
```

不是视频，不是 GIF，是 **DOM + CSS + GSAP timeline** 组成的程序化演示。

### 1.2 为什么不用录屏或 GIF

| 方式 | 问题 |
|---|---|
| 视频 | 体积大（一段 2 分钟录屏 9 MB）；不能改文案；分辨率固定 |
| GIF | 体积更大；色彩差；不能暂停在某一帧 |
| **DOM 动画** | 几十 KB；文案可改；可随时改动一屏；支持 `prefers-reduced-motion` |

### 1.3 整体流程

```text
录屏 → ffprobe 探参数 → 三档抽帧 → 逐帧记界面
     → 搭外壳 → 写积木 → 编排时间轴 → 核对光标
     → 脱敏扫描 → 部署验证
```

### 1.4 三条最容易踩的线

1. **照录屏逐帧做，不要凭记忆。** 凭记忆做的界面一定会返工。
2. **隐私当场脱敏，不要留到最后。** 从录屏抄界面时，真实姓名、金额、卡号会一起抄进代码。
3. **光标坐标要在播放时算，不要在构建时算。** 构建时页面还没切换，算出来必然错位。

## 2. 视频 → 抽帧 → 读界面

### 2.1 装 ffmpeg

**Windows**：唯一稳定的方式是 BITS 传输。

```powershell
# 先定义工具目录，后面所有命令都复用它
$TOOLS = "$env:USERPROFILE\tools"        # 换到你的实际位置，例如 D:\tools
New-Item -ItemType Directory -Force -Path "$TOOLS\ffmpeg" | Out-Null

Start-BitsTransfer `
  -Source 'https://github.com/GyanD/codexffmpeg/releases/download/9.0.2/ffmpeg-9.0.2-essentials_build.zip' `
  -Destination "$TOOLS\ffmpeg\ff.zip"
Expand-Archive -Path "$TOOLS\ffmpeg\ff.zip" -DestinationPath "$TOOLS\ffmpeg" -Force
```

**装到项目之外的固定位置**，不要放项目内的临时目录，否则清目录时会被连坐删掉。

**本档后面统一用 `$FFDIR` 表示 ffmpeg 的 bin 目录**，使用时替换成你的实际路径：

```bash
# 先设置一次，后面所有命令都复用它
FFDIR="$HOME/tools/ffmpeg/ffmpeg-9.0.2-essentials_build/bin"
"$FFDIR/ffprobe.exe" -version
```

**不要把 ffmpeg 加到系统 PATH**：不同 shell 的 PATH 不共享，用绝对路径更可靠。

> **为什么不在 bash 里 `export PATH=...`**：每次 bash 调用都是新 shell，`export` 不跨调用生效，会得到 `ffprobe: command not found`。

**macOS**：`brew install ffmpeg`。**Linux**：`sudo apt install ffmpeg`。

### 2.2 先探测，别急着抽帧

```bash
"$FFDIR/ffprobe.exe" -v error \
  -show_entries format=duration,size \
  -show_entries stream=width,height \
  -of default=noprint_wrappers=1 \
  "你的录屏.mp4"
```

输出形如：

```text
width=416
height=960
duration=123.559250
size=9371352
```

**三个数决定后续所有参数**：

| 字段 | 决定什么 |
|---|---|
| `duration` | 抽帧密度（2 分钟不可能逐秒看） |
| `width` / `height` | `scale` 参数，竖屏与横屏要区别对待 |
| `size` | 是否要压缩存档 |

### 2.3 三档抽帧

设在 `VIDEO` 变量上，后续命令都复用它：

```bash
VIDEO="你的录屏.mp4"
FF="$FFDIR/ffmpeg.exe"
```

**第一档：粗扫（每 5 秒）**，先摸清结构。

```bash
"$FF" -v error -i "$VIDEO" -vf "fps=1/5,scale=416:-1" ".run/vid/f_%03d.png" -y
```

2 分钟 → 约 25 帧。用来回答「哪一段是哪一屏」。

**第二档：细扫（每 3 秒，可截断）**。

```bash
"$FF" -v error -i "$VIDEO" -t 96 -vf "fps=1/3,scale=416:-1" ".run/vid/w_%03d.png" -y
```

`-t 96` 只取前 96 秒。当前后两段是不同流程时，分开抽更清楚。

**第三档：逐秒（全片）**，用来抓每个动作的准确时间点。

```bash
"$FF" -v error -i "$VIDEO" -vf "fps=1,scale=320:-1" ".run/vid/s_%03d.png" -y
```

124 帧时把 `scale` 降到 320：单张体积小一半，读图成本低。

**怎么判断该抽多密**：粗扫时若相邻两帧界面明显跳变（6 秒还在 A 页、9 秒已到 B 页），说明该段要加密。

**产物一律放临时目录**，不进版本库。

### 2.4 把帧真正读进来，再记五项

#### 1.4.1 先弄清楚：抽帧不等于看过

`ffmpeg` 抽完只会给你一堆 png **文件名**（`s_001.png`、`s_002.png`…）。
**看到文件名不等于看到画面。**

你可以直接 `ls` 出一长串文件名，然后凭想象写代码 —— 这是本流程里最贵的一种错，
因为你可以完全不知道自己在漏东西。

**必须做的一步**：用 `read` 工具把图片文件打开。

```text
read E:\path\to\s_004.png
```

`read` 会把 PNG 解码成图像送进你的视觉输入。这时你才真的「看见」了：
导航栏写了什么、一行有几个元素、图标什么颜色、间距多大。

**没有调用 `read` 打开过某个 png，你对它的任何描述都是编的。**

#### 1.4.2 挑帧：先排除没有内容的帧

一个 124 帧的录屏里，可能有 20–30 帧是过渡态。**先看，再判断要不要用**：

```text
read s_001.png   → 我页，有头像和列表          → 可用
read s_004.png   → 钱包页，4 组 10 行          → 可用（这是基准）
read s_010.png   → 只有 ✕ + 进度条，内容区全白  → 废帧，跳过
```

**判据**：这一帧里有没有**至少一行完整内容**（图标 + 文字 + 右侧值）。

| 废帧特征 | 说明 |
|---|---|
| 只有进度条 / 只有标题 | 加载中 |
| 整片白或整片灰 | 刷新中 |
| 两个界面叠在一起 | 转场中 |
| 黑屏 + 系统提示 | 被遮挡 |

**废帧不能当基准**。实测过：拿一张空白过渡帧做比对基准，得出的差异表
13 项全是 ✗，报告完全不可用。审查者甚至把「实现里有内容」判成了错误。

#### 1.4.3 每屏挑一张基准帧

> **注意成本**：逐帧读图很慢。实测挑一屏的基准帧，读了十几帧花了 15–20 分钟。
>
> **省时办法**：先用粗扫的 `fps=1/5` 那 25 帧定位（每屏大概率覆盖到了），
> 只在必要时才去翻逐秒的 124 帧。


同屏内容可能在多帧里出现（滚动前后）。**挑元素最全的那一张**：

| 屏 | 建议选 | 理由 |
|---|---|---|
| 列表页 | 滚动到顶部的第一帧 | 第一行到最后一组标签都在 |
| 表单页 | 所有输入框都填好之后那一帧 | 能看到真实内容长度 |
| 结果页 | 出现结果后停 1 秒那一帧 | 文字已经稳定，不会重排 |

把选定的帧路径记进屏清单，后面截图比对时直接用这张：

```text
屏清单表加一列：基准帧
| # | 屏名 | 基准帧 | ... |
| 1 | 钱包 | .run/vid/w2/s_004.png | ... |
```

#### 1.4.4 铁律：一次只能读一张图

**这一条比任何技巧都重要。** 实测代价：一次误操作导致 8 分钟、83 次无效调用。

**事实**：

| 一批读几张 | 结果 |
|---|---|
| 1 张 | ✓ 准确，约 3 秒 |
| 3 张 | ✓ 准确，约 9 秒 |
| 5 张 | ✗ **只有第一张进入上下文**，其余被丢弃 |

**症状长什么样**：`read` 返回 `ok`，格式也正常（`[Image: original 960x66, ...]`），
但你就是看不见内容。这时**不要**：

- 换路径写法（`E:/` vs `E:\`）
- 复制文件、改名字
- 转成 JPG
- 放大尺寸
- 加 `:raw`

**这些全是无效自救。** 实测那个 AI 试了上面所有办法，消耗 83 次请求，
最后还是只读出 1 行。**真正的原因只有一个：一次塞了太多张。**

**正确做法**：

```text
read row01.png      → 立刻写一行结果
read row02.png      → 立刻写一行结果
read row03.png      → 立刻写一行结果
```

**三条硬规则**：

1. **一次一个 `read`**，不要在一批里发多个
2. **读完立刻写下结果**，不要攒到最后一起回忆
3. **看不到就写「看不到」，继续下一张**，不要回头重试

**实测验证**（同一批 10 张图，两种做法对比）：

| 做法 | 结果 | 耗时 |
|---|---|---|
| 一次发 5 个 read | 只有第一张能看到，其余丢失 | 8 分钟 83 次调用仍失败 |
| 逐个发 + 读完即写 | **10 张全部读到，内容全对** | **59 秒** |

第二种做法读出的内容：

```text
1: 零钱 ¥20.00 >              6: 分付 买新品手机享24期免息 可用¥33.56 >
2: 经营账户 >                  7: 支付分 >
3: 零钱通 收益率0.85% ¥0.00 >   8: 支付设置 >
4: 银行卡 >                    9: 身份信息 >
5: 亲属卡 >                   10: 客服中心 >
```

**「读完即写」为什么重要**：图像在上下文里会被后续内容挤出。
攒到最后一起写，前面的图已经看不到了。

#### 1.4.4.1 看不到图时的判断顺序

按这个顺序排查，不要跳步：

| 步骤 | 检查 | 处理 |
|---|---|---|
| 1 | 这一批是不是读了好几张？ | 改成一次一张，重试 |
| 2 | 还是看不到？ | 换一张**内容明显不同**的图（如导航栏 vs 某一列表行） |
| 3 | 单张也看不到？ | 这次才是模型/工具问题，见下表 |

**单张仍看不到时**：

| 方案 | 可行 |
|---|---|
| 换一个能读图的模型 | ✓ 首选 |
| 用本地 OCR（如 RapidOCR） | ✓ 次选：脚本 OCR → JSON → 你读 JSON |
| 靠像素分析硬猜文字 | ✗ 不可能 |
| 放弃逐字复刻，只做结构复刻 | ✓ |

**先测再决定**：`read` 一张图，然后回答「图里第一个图标是什么颜色」。
答得出就走视觉路线，答不出才上图里的方案。

#### 1.4.4.2 先切图，再读图（这一步不能省）

**整帧 320px 宽时，汉字只有 11–13px，直接看是模糊的。** 必须切行放大。

用脚本一次切完（脚本在 `docs/reference/assets/frame-crop.py`）：

```bash
python frame-crop.py 基准帧.png --outdir crops/
```

**3 秒完成**，产出：

```text
crops/
  row01.png … row10.png   每行一张，放大 5 倍
  group01.png …           每 3 行合成一张，减少读图次数
  summary.json            数出来的结构
  index.md                给视觉模型看的清单
```

**放大倍数与视觉能力有关，分两档**：

| 你的情况 | 用什么 | 说明 |
|---|---|---|
| **能看清 row01.png（5 倍全宽）** | 直接用，不用额外处理 | 多数模型属于这档 |
| **看不清** | 用「窄窗 × 高倍」：只截文字区，8–14 倍 | 视觉分辨率较弱的模型 |

**窄窗裁图的规则**（看不清时用）：

```text
宽度：从标题左边界到右侧值左边界（约原图 x=60..200）
高度：一行
倍数：8–14
一次只含一行、不含图标、不含右侧金额
```

实测：一个 AI 用 5 倍全宽图读不出「翼来租」，
改用 140px 宽 × 14 倍后能读出（仍错了一个字，写成「巽来租」）。

**合成图的用途有限**：

`group01.png`（3 行竖拼）适合**快速过一遍**，不适合逐字认。
它把 3 行拼成一张后，渲染时会被压回 1568px 宽，等效放大倍数约等于 5/3。
**认字用单行图**，合成图只用来确认「这几行大致是什么」。

**判断自己属于哪一档**：切完图后先读 `row01.png`，能准确读出主标题就是第一档；
读错或读不出，切到窄窗高倍方案。

`index.md` 长这样：

```markdown
## 像素数出来的结构（这部分不用你看，直接用）
- 卡片：3 张
- 行：10 行
- 右侧箭头：10 个
- 图标颜色：黄 #f6e98b、绿 #83dbb6、青 #83d3ed、蓝 #87bfe4、橙 #edcb8b

## 每行配图（请逐张 read 打开，记下文字）
| 卡 | 行 | y 中心 | 图 |
| 1 | 1 | y=92 | row01.png |
| 1 | 2 | y=139 | row02.png |
...
```

**分工明确**：

| 谁做 | 做什么 |
|---|---|
| 脚本（像素分析） | 数：卡片、行、箭头、颜色。这些有确定答案 |
| 视觉模型（read 裁图） | 认：文字、图标形状、颜色深浅 |

**不要试图让视觉模型数行数，也不要让脚本认字。** 各做各擅长的。

> **有视觉能力时不要装 OCR**：实测 RapidOCR 把 `¥33.56` 读成 `?33.56`、
> 把图标读成「司」「日」「圆」，准确率不如直接看 5 倍裁图，
> 还要多装 400MB 依赖、首次运行下模型。
>
> **没有视觉能力时才用 OCR**（见 §1.4.4）。此时流程变成：
> `frame-crop` 切图 → RapidOCR 逐行识别 → 输出 JSON → 你读 JSON。
> 脚本里已经预留了 `--no-ocr` 开关，加回去即可。

#### 1.4.5 然后才记五项

看完图，记这五项：

| 字段 | 记什么 | 例子（账单页） |
|---|---|---|
| **导航结构** | 顶部有什么、标题在哪、右侧有什么 | `✕` + 居中「账单」+ 右侧 ⊙ |
| **控件与状态** | 有哪些按钮、哪个选中 | 两个胶囊：`全部账单 ▾` / `查找交易` |
| **文案原文** | 逐字抄，含标点 | 「可根据账单用途下载…（包括已删除的交易）。」 |
| **数值与颜色** | 哪个数字是什么色 | 支出（黑）/ 收入（**黄**） |
| **交互路径** | 点这里会去哪 | 点「用于个人对账」→ 下一屏 |

**文案要逐字抄**，包括标点、空格、省略号位置。真机的「…」和「...」不是一回事。

**颜色要写清是哪个元素**。只写「收支有颜色区分」，写代码时必然猜错。

#### 1.4.6 止境：读到什么程度就停

**读图会无限进行下去。** 本次实测：一个 AI 读一屏读了 24 分钟、151 次请求还没写完代码，
因为它一直在纠结「这个字是 3 还是 5」「这里差 1px」。

**必须设止境。** 按下面的标准停：

| 项 | 读到什么程度停 |
|---|---|
| 组数 / 行数 | **必须精确**，用像素校验（§10.5.0.3） |
| 文案 | 读到能读清为止；看不清的标 `[UNSURE]` 并跳过 |
| 颜色 | 取一个代表性色值即可，不必逐像素比对 |
| 字号 | 估到整数即可，不要纠结 12 还是 12.5 |
| 间距 | 允许 ±2px 误差，不要逐项量 |
| 图标形状 | 能看出是什么类别即可（圆形 / 方形 / 花朵） |

**硬性上限**：

| 限制 | 数值 | 理由 |
|---|---|---|
| 每次 `read` 的图数 | **1 张** | 多张只有第一张能看见（§1.4.4） |
| 单屏总 `read` 次数 | **行数 + 3** | 每行一次，加导航/页头/页尾 |
| 同一文件重读次数 | **0** | 重读拿不到新信息，只是浪费 |
| **读图阶段总时长** | **10 分钟** | 超时必须进入写代码阶段 |

##### 读图不是写代码的前置条件

**这是最容易卡死的地方。** 实测一个 AI 因为「必须读全 9 行才敢写代码」，
14 分钟 126 次请求一直在切图，一个字都没写进场景。

**正确心态**：读图是**渐进**的，不是一次到底。

```text
第 1 轮：读完前 3 行 → 立刻写场景骨架（3 行内容 + 结构）
第 2 轮：截图比对 → 发现少了 6 行 → 补 3 行
第 3 轮：再比对 → 补剩下的
```

**允许在只读了一部分时就开始写代码。** 结构（卡片数、行数、箭头数）
由 `frame-crop.py` 提前给出，比文案更可靠，先按结构搭好框架。

**读不清的文案怎么办**：

1. 标 `[UNSURE]`，按最可能的猜测写进代码
2. `screens.json` 的 `mustContain` **只放已确认的**
3. 未确认的用 `minStats` 兜底（行数、箭头数、图标数都是可靠的）
4. 进入截图比对阶段，用差异驱动补

**判断标准**：读图阶段超过 10 分钟就停。
停下来写代码不等于放弃，是换一种方式推进。

##### 怎么自检「我在抠细节」

没法精确计时时，用这两个可数的锚点：

| 锚点 | 阈值 | 触发后 |
|---|---|---|
| 已读图张数 | > 行数 + 3 | 停止读，进入写代码 |
| 已切图次数（生成新的裁剪文件） | > 3 次 | 停止切，说明切法不对或图看不清 |

**第二个锚点专治本案例**：那个 AI 一直重新切图（`r8x`、`a1-a8`、`b1-b3`、`t1-t2`），
切了 15 次以上。**切图超过 3 次说明方向错了**，不是图的问题，是方法的问题。

**遇到看不清的正确反应**（按顺序）：

1. 换窄窗高倍切法（§1.4.4.2 的两档方案）
2. 还是看不清 → 标 `[UNSURE]`，继续下一行
3. 整屏都看不清 → 放弃逐字复刻，只做结构复刻，文案留占位

**不要做的**：反复调倍数、反复截不同区域、转格式。
这三件事实测都被试过，全部无效。

**正确的循环是「粗读 → 写 → 比对 → 精修」，不是「一次读到底」。**

##### 读不清时的退出口（这是必须有的机制）

实测有一个 AI 卡在这里：放大裁图后中文小字仍是模糊块，
反复重读 24 分钟、151 次请求，始终不敢开始写代码。

**明确规则：读不清就标，标完立刻继续。**

```
记录格式：
| 行 | 文案 | 状态 |
| 2  | 零钱通 + 收益率0.85% | [确认] |
| 4  | 银行卡 | [确认] |
| 5  | ???? | [UNSURE：裁图模糊，疑似「亲属卡」，待截图比对时确认] |
```

**标注后的处理顺序**：

1. **先按最可能的猜测写代码**（猜测写进 `[UNSURE]` 备注）
2. 写完后截图比对，用**布局宽度**反推：一个 4 字标签约占 56px，3 字约占 42px
3. 拿不准的文案，**不影响结构就先放着**，它不影响组数/行数/图标数这些硬指标

**禁止**：
- 对同一区域反复 read（`read` 会返回缓存提示，重读同一文件拿不到新信息）
- 因为个别字看不清就停住不动
- 把猜测当确认写进 `screens.json` 的 `mustContain`（会变成假失败）

**`mustContain` 只放已确认的文案。** 不确定的等截图比对阶段再补。

#### 1.4.7 自检：你记的东西能不能对上图

写完五项，**再打开一次那张图**，逐条对：

- 记的行数，和图上数的一致吗？
- 记的图标颜色，每个都写了吗？
- 记的文案，是图上原文还是你以为的？

**对不上的地方立刻改。** 这一步花 1 分钟，能省掉后面一轮返工。

#### 1.5.2 从截图量尺寸

录屏分辨率不等于你的画布尺寸，必须换算。

**举例：设你的画布是 560×700，录屏是 416×960 的手机竖屏。**

手机在录屏里占的宽度，就是它在画布里的宽度：

```text
录屏里手机宽 ≈ 屏幕宽 - 两侧留白
→ 画布 560 宽时，手机取 320 宽（留 120 两侧）
→ 高度按录屏比例：320 × (960 / 416) ≈ 738，但画布只有 700
→ 所以取 320 × 668，留出上下 16px
```

**字号换算**（录屏里量出像素，按手机宽比缩放）：

```text
录屏手机宽 W1，画布手机宽 W2
scale = W2 / W1

录屏里 13px 的字 → 画布里 13 × scale
例：W1 = 416, W2 = 320 → scale = 0.77 → 13 × 0.77 ≈ 10px
```

**更省事的办法**：量三处就够了，其余靠视觉调。

| 量什么 | 怎么量 |
|---|---|
| 手机外框 | 录屏里手机的左右边界像素差 |
| 导航栏高 | 从导航栏顶线到底线的像素差 |
| 正文字号 | 找一行字，量字高（不是行高） |

其余尺寸按同一个 `scale` 换算，不必逐项量：

| 项 | 公式 | 例子（scale=0.77） |
|---|---|---|
| 字号 | `录屏字号 × scale` | 13px → 10px |
| 行高 | `录屏行高 × scale`，或用 `字号 × 1.3~1.5` | 10px × 1.4 = 14px |
| 行内边距 | `录屏内边距 × scale` | 14px → 11px |
| 图标尺寸 | `录屏图标边长 × scale` | 34px → 26px |
| 圆角 | `录屏圆角 × scale`，但不要低于 3px | 6px → 4.6px |

**写代码时取整数**，不必保留小数。差 1–2px 肉眼看不出来；
差 4px 以上再对着截图修。

#### 1.5.4 通用的「建行」函数

上面用到的 `group()` 与 `row()` 是最常写的两个积木。放进 `kit.js`：

```js
/** 一组行（白底卡片）。top 控制与上一组的间距。 */
export function group(parent, { top = 0 } = {}) {
  const g = document.createElement("div");
  g.style.cssText =
    `background:#fff;margin-top:${top}px;`;
  parent.appendChild(g);

  return {
    el: g,
    row(label, { icon = "", iconColor = "#999", note = "", value = "", chevron = true } = {}) {
      const r = document.createElement("div");
      r.style.cssText =
        "display:flex;align-items:center;gap:8px;padding:9px 12px;" +
        "border-bottom:1px solid #f0f0f0;cursor:pointer;";
      if (icon) {
        const i = document.createElement("i");
        i.textContent = icon;
        i.style.cssText =
          `flex:0 0 auto;display:grid;place-items:center;width:27px;height:27px;` +
          `border-radius:5px;background:${iconColor};color:#fff;font-size:13px;font-style:normal;`;
        r.appendChild(i);
      }
      const mid = document.createElement("div");
      mid.style.cssText = "flex:1;min-width:0;display:flex;flex-direction:column;line-height:1.3;";
      const b = document.createElement("b");
      b.textContent = label;
      b.style.cssText = "font-size:14px;font-weight:400;";
      mid.appendChild(b);
      if (note) {
        const s = document.createElement("span");
        s.textContent = note;
        s.style.cssText = "font-size:10px;color:#9a9a9a;";
        mid.appendChild(s);
      }
      r.appendChild(mid);
      if (value) {
        const v = document.createElement("em");
        v.textContent = value;
        v.style.cssText = "font-size:12px;color:#666;font-style:normal;";
        r.appendChild(v);
      }
      if (chevron) {
        const c = document.createElement("span");
        c.textContent = "\u203A";
        c.style.cssText = "color:#c8c8cd;font-size:16px;";
        r.appendChild(c);
      }
      g.appendChild(r);   // 少了这行，行不会出现在页面上
      return r;
    },
  };
}
```

### 2.6 识别过渡帧，别把它当界面

**四类容易误判的帧**：

| 样子 | 实际是什么 |
|---|---|
| 只有进度条 / 只有标题没内容 | 页面加载中 |
| 整片白或整片灰 | 浏览器刷新中间态 |
| 黑屏 + 「涉及隐私的内容不会被录制」 | 系统遮挡，无内容 |
| 光标停在奇怪位置（如说明文字上） | 抓到了移动动画的中间帧 |

**识别方法**：

- 元素残缺（只有进度条）
- 相邻帧布局严重不一致
- 出现「正在加载」「刷新」
- 黑屏或纯色 + 系统提示

**抓到疑似过渡帧，前后各多看两帧**，确认它是过程还是结果。

### 2.7 多个视频要先分清用途

| 用途 | 特征 |
|---|---|
| **复刻对象** | 你要一帧帧照做的那段，通常是**你自己录的** |
| **手感参考** | 别人做得好、你要学它节奏的那段 |

拿到多个视频时先问清哪个是「照它做」、哪个是「照它的手感做」。

### 3.2 `stage.js`（完整可复制）

```js
/**
 * 演示舞台。只需 GSAP，不依赖框架。
 */
export const SCREEN_W = 560;
export const SCREEN_H = 700;

export function createStage(host, gsap) {
  const box = document.createElement("div");
  box.className = "stage-box";
  const screen = document.createElement("div");
  screen.className = "stage-screen";
  const bar = document.createElement("div");
  bar.className = "stage-bar";
  const barFill = document.createElement("i");
  bar.appendChild(barFill);
  box.appendChild(screen);
  host.appendChild(box);
  host.appendChild(bar);

  screen.style.width = `${SCREEN_W}px`;
  screen.style.height = `${SCREEN_H}px`;
  barFill.style.transformOrigin = "left center";

  let tl = null;
  let barTween = null;
  let scenes = [];
  let currentKey = null;

  const fit = () => {
    const w = box.clientWidth || SCREEN_W;
    const s = Math.min(1, w / SCREEN_W);   // 只缩不放
    screen.style.transform = `scale(${s})`;
    box.style.setProperty("--stage-scale", String(s));
  };
  const ro = new ResizeObserver(fit);
  ro.observe(box);
  fit();

  const teardown = () => {
    if (tl) { tl.kill(); tl = null; }
    if (barTween) { barTween.kill(); barTween = null; }
    // 光标移动用的是独立补间（不受 timeline 管辖），必须单独杀掉，
    // 否则切场景后旧场景的光标还在跑
    const cur = screen.querySelector(".d-cursor");
    if (cur && cur._cursorTweens) {
      cur._cursorTweens.forEach((t2) => t2.kill());
      cur._cursorTweens = [];
    }
    screen.innerHTML = "";
    gsap.set(barFill, { scaleX: 0 });
  };

  const show = (key) => {
    const entry = scenes.find((s) => s.key === key);
    if (!entry) { console.warn(`[stage] 未注册的场景：${key}`); return; }
    teardown();
    currentKey = key;

    // 场景内部不要再建 timeline：paused 的子 timeline 不跟随父级播放
    tl = gsap.timeline({ paused: true });
    entry.build({ root: screen, tl, gsap });
    const total = tl.duration();

    barTween = tl.fromTo(
      barFill,
      { scaleX: 0 },
      { scaleX: 1, duration: Math.max(total, 0.1), ease: "none" },
      0,
    );
    tl.play(0);
  };

  return {
    show,
    setScenes(list) { scenes = list; },
    get current() { return currentKey; },
    pause() { if (tl) tl.pause(); },
    resume() { if (tl) tl.play(); },
    restart() { if (tl) tl.restart(); },
    destroy() { teardown(); ro.disconnect(); host.innerHTML = ""; },
  };
}
```

### 3.3 `kit.js`（光标与常用积木）

> **`h()` 的类名会自动加 `d-` 前缀。**
> `h("div", "pill is-on")` 得到的是 `class="d-pill d-is-on"`，**不是** `d-pill is-on`。
> 所以状态类必须用 `flag(el, "on")`，或者自己写 `el.classList.add("is-on")`。
> CSS 里对应的选择器是 `.d-pill.is-on`。混用会让高亮/选中态静默失效。

```js
/** 建元素。注意：这个 h() 会自动给 class 加 "d-" 前缀。 */
const NS = "d";
export function h(tag, cls, parent) {
  const el = document.createElement(tag);
  if (cls) el.className = cls.split(" ").map((c) => `${NS}-${c}`).join(" ");
  if (parent) parent.appendChild(el);
  return el;
}

// 状态类（is-on / is-active / is-hidden…）走这个，不要塞进 h() 的第二个参数。
// h() 会给每一段都加前缀：h("div","pill is-on") → class="d-pill d-is-on"，
// 而 CSS 写的是 .d-pill.is-on，选择器匹配不上（实测踩过，胶囊高亮完全失效）。
export function flag(el, name, on = true) {
  el.classList.toggle(`${NS}-${name}`, on);
  return el;
}

/**
 * 光标：一个圆点 + 一圈波纹。
 * 用法：
 *   const cur = cursor(root);
 *   cur.show(tl, 0.5);
 *   cur.toAt(tl, button, { duration: 0.4, at: ">" });
 *   cur.click(tl, button, ">");
 */
export function cursor(root) {
  const el = h("div", "cursor", root);
  const dot = h("div", "cursor-dot", el);
  const ring = h("div", "cursor-ring", el);
  el.style.opacity = "0";

  let curX = 0;
  let curY = 0;
  const apply = () => {
    el.style.transform = `translate(${curX}px, ${curY}px)`;
  };
  apply();

  /**
   * 算出目标中心相对场景的坐标。
   * 三道保护缺一不可，否则光标会被甩到画外。
   */
  const moveTo = (target) => {
    const box = root.getBoundingClientRect();
    const rect = target.getBoundingClientRect();
    const logicalW = root.offsetWidth || box.width;
    const scale = logicalW ? box.width / logicalW : 1;

    // 1 目标尺寸为 0（隐藏页、display:none 的祖先）
    if (!rect.width || !rect.height) return null;
    // 2 整条祖先链都没渲染
    if (target.offsetParent === null && getComputedStyle(target).position !== "fixed") return null;

    const x = (rect.left + rect.width / 2 - box.left) / (scale || 1);
    const y = (rect.top + rect.height / 2 - box.top) / (scale || 1);

    // 3 落点必须落在场景范围内
    const w = root.offsetWidth || box.width;
    const hh = root.offsetHeight || box.height;
    if (x < 0 || y < 0 || x > w || y > hh) return null;

    return { x, y };
  };

  return {
    el,
    show(tl, at = 0) {
      tl.to(el, { opacity: 1, duration: 0.25 }, at);
      return tl;
    },
    /**
     * 关键：坐标必须在 tl.call 里算，不能在构建时算。
     * 构建时菜单没弹出、页面没切换，取到的是起始状态。
     */
    toAt(tl, target, opts = {}) {
      tl.call(() => {
        const p = moveTo(target);
        if (!p) return;
        if (p.x === curX && p.y === curY) return;
        // 用局部对象，不要用 this.targets()[0]：
        // 后者在压缩后的 GSAP 里读不到，光标会一动不动
        const state = { x: curX, y: curY };
        // 记下这个补间，切场景时要能一起杀掉
        if (!el._cursorTweens) el._cursorTweens = [];
        const tw = window.gsap.to(state, {
          x: p.x, y: p.y,
          duration: opts.duration ?? 0.45,
          ease: "power2.inOut",
          onUpdate() {
            curX = state.x;
            curY = state.y;
            apply();
          },
        });
        el._cursorTweens.push(tw);
      }, null, opts.at ?? ">");
      return tl;
    },
    /** 只画波纹，不再移动光标。场景里已先 toAt 定位。 */
    click(tl, target, at = ">") {
      tl.fromTo(ring,
        { scale: 0.4, opacity: 0.9 },
        { scale: 1.6, opacity: 0, duration: 0.5, ease: "power2.out" },
        at);
      return tl;
    },
    hide(tl, at = ">") {
      tl.to(el, { opacity: 0, duration: 0.2 }, at);
      return tl;
    },
  };
}

/** 逐字打印。 */
export function type(tl, el, text, { cps = 18, at = ">" } = {}) {
  const chars = [...text];
  const state = { n: 0 };
  tl.call(() => { el.textContent = ""; }, null, at);
  tl.to(state, {
    n: chars.length,
    duration: Math.max(0.2, chars.length / cps),
    ease: "none",
    onUpdate() { el.textContent = chars.slice(0, Math.round(state.n)).join(""); },
  }, "<");
  return tl;
}

/** 右下角成功印章。 */
export function ok(root, text, { en = "" } = {}) {
  const el = h("div", "ok", root);
  el.innerHTML = `<b>${text}</b>${en ? `<span>${en}</span>` : ""}`;
  el.style.opacity = "0";
  return (tl, at = ">") => {
    tl.to(el, { opacity: 1, duration: 0.28, ease: "back.out(2)" }, at);
    return tl;
  };
}
```

### 3.7 三处尺寸必须同步（但尺寸本身应由基准帧决定）

**先说尺寸怎么定，再说同步**。

#### 2.7.1 画布尺寸取基准帧的宽高比

文档示例用 `560×700`，**那只是举例，不是规定**。正确做法：

```text
基准帧 320×738  → 画布可以取 320×738（1:1，最省事）
                 也可以整体放大 2 倍取 640×1476
                 ★ 但宽高比必须与基准帧一致，否则外壳被压扁
```

**实测踩过**：一个 AI 拿到 320×738 的基准帧，照文档写死 `560×700`，
结果外壳被压扁 70px，只能回头改三个地方。

**换算规则**：

```text
画布宽 = 基准帧宽 × n
画布高 = 基准帧高 × n        ← 必须同比，不能各自取整
n 取 1 或 2（1 最省事，2 更清晰）
```

#### 2.7.2 然后三处同步

改尺寸必须同时改这三处：


| 位置 | 值 |
|---|---|
| `stage.js` 的 `SCREEN_W` / `SCREEN_H` | `560` / `700` |
| `demo.css` 的 `.stage-screen` | `width: 560px; height: 700px` |
| `demo.css` 的 `.stage-box` 的 `aspect-ratio` | `560 / 700` |

**三处不一致不会报错，只会让光标纵向偏移**：`box` 的高度由 `aspect-ratio` 决定，光标按 `box` 坐标算，目标按实际布局算，两者对不上。

### 4.2 页容器：四项缺一不可

```js
export function createPage(shell, { prefix = "p" } = {}) {
  const p = document.createElement("div");
  p.className = `${prefix}-page`;
  p.style.cssText =
    "position:absolute;inset:0;overflow-y:auto;overflow-x:hidden;" +
    "scrollbar-width:none;padding-bottom:8px;box-sizing:border-box;display:none;";
  shell.body.appendChild(p);
  return p;
}
```

| 属性 | 缺了会怎样 |
|---|---|
| `position:absolute; inset:0` | 页面不叠在内容区，全部纵向排列 |
| `overflow-y:auto` | 内容超一屏被裁掉 |
| `padding-bottom:8px` | 滚到底时最后一行贴边 |
| `display:none` | 所有页同时可见 |

`box-sizing:border-box` 必须配 `padding-bottom`，否则 padding 会把内容顶出可视区。

### 4.3 切页函数

```js
export function go(tl, from, to, at = ">") {
  tl.call(() => { to.style.display = "block"; }, null, at);
  tl.fromTo(to, { opacity: 0, x: 12 }, { opacity: 1, x: 0, duration: 0.26 }, at);
  tl.to(from, { opacity: 0, duration: 0.18 }, at);
  // 最后一步必须用 ">"，不能写 at + 0.18
  tl.call(() => {
    from.style.display = "none";
    from.style.opacity = 1;
  }, null, ">");
}
```

> **`at` 是字符串位置**（`">"`、`">+0.9"`），对它做算术会得到 `">+0.90.18"` 这种非法值。
> **GSAP 不报错，只是永不执行**，结果是上一页永远不消失，页面越叠越多。

### 4.4 页容器上不许写 `display`

**错误**：

```css
.my-page.is-fullscreen { display: flex; }   /* 这一页永远压在最上面 */
```

**正确**：布局放内层。

```js
const inner = document.createElement("div");
inner.style.cssText = "position:absolute;inset:0;display:flex;flex-direction:column;";
page.appendChild(inner);
```

原因：`go()` 用内联 `display:none` 隐藏页面，而带类的 `display:flex` 优先级更高，隐藏不生效。

### 5.1 光标不可见：类名前缀被加了两次

如果 `h()` 会自动加前缀（如 `d-`），那么：

```js
h("div", "cursor")     // ✓ → class="d-cursor"
h("div", "d-cursor")   // ✗ → class="d-d-cursor"，匹配不到样式
```

**判据**：改完必须量 DOM。

```js
document.querySelector(".d-cursor-dot").getBoundingClientRect().width  // 必须 > 0
```

### 5.2 坐标在构建时就算，落点偏 97px

**错误**：

```js
toAt(tl, target) {
  const p = moveTo(target);           // 构建时算
  tl.to(el, { x: p.x, y: p.y }, at);
}
```

场景构建时，菜单还没弹出、页面还没切换，`getBoundingClientRect()` 拿到的是**起始状态**。

**正确**：放进 `tl.call`，播放时才算（见 §3.3 的完整实现）。

**实测偏差**：目标中心 `(616, 269)`，光标落在 `(710, 245)`，偏 97px。

### 5.3 目标还在位移中，坐标取到中间值

若卡片有 `y: 12 → 0` 的入场动画，而 `toAt` 在同一时刻取坐标，拿到的是**元素还在位移中的位置**。

**统一规则（两个场景都适用）**：

| 情况 | 安全间隔 |
|---|---|
| 元素自己的入场动画（`y: 12`，0.35s） | `at` 至少排在动画结束后 **0.1 秒** |
| 切页之后（`go()` 刚把新页设成 block） | `at` 至少 **0.5 秒**（要等布局完成 + 动画启动） |

**别猜，用这两个数**：

```js
// 入场动画 0.35s，从 0.1s 开始 → 0.45s 结束
tl.from(card, { opacity: 0, y: 12, duration: 0.35 }, 0.1);
cur.toAt(tl, btn, { duration: 0.5, at: 0.6 });   // 0.45 + 0.15 ✓

// 切页
go(tl, p1, p2, ">");
cur.toAt(tl, nextRow, { duration: 0.5, at: ">+0.5" });   // ✓ 不是 ">+0.1"
```

```js
tl.from(card, { opacity: 0, y: 12, duration: 0.35 }, 0.1);
cur.show(tl, 0.5);
cur.toAt(tl, btn, { duration: 0.5, at: 0.9 });   // 0.35 + 0.1 = 0.45，0.9 足够
```

### 5.4 GSAP 的 `this.targets()` 在压缩版里读不到

**现象**：`[toAt]` 打印出正确坐标，但光标一动不动。

**根因**：

```js
gsap.to(state, {
  x: p.x,
  onUpdate() {
    curX = this.targets()[0].x;   // 压缩后 this 上下文不可靠，读不到
  },
});
```

**正确**：用局部变量持有目标对象。

```js
const state = { x: curX, y: curY };
gsap.to(state, {
  x: p.x,
  onUpdate() {
    curX = state.x;
    apply();
  },
});
```

### 5.5 切页后立刻定位，会被跳过

**现象**：多屏演示里，光标停在第一屏不动，后面几屏的点击全部落空。

**根因**：`go()` 用 `tl.call` 把新页设成 `display:block`，而 `toAt` 的 `moveTo` 有一道保护：

```js
if (target.offsetParent === null && getComputedStyle(target).position !== "fixed") return null;
```

如果 `toAt` 和 `go()` 排在**同一时刻**，`offsetParent` 还是 `null`，`moveTo` 返回 `null`，光标被跳过。

**修法**：给 `toAt` 留出至少 0.3 秒余量。

```js
go(tl, p2, p3, ">");
cur.toAt(tl, nextRow, { duration: 0.5, at: ">+0.8" });   // 不是 ">"
```

**验证方法**：数一下 `[toAt]` 打印的条数，再数一下场景里写的 `toAt` 条数，少了就是被跳过。

### 5.6 `click()` 重复移动光标

若 `toAt` 已定位，`click()` 里再调一次会取到**页面淡出中的**坐标。

**正确**：`click()` 只画波纹。

### 5.7 目标在隐藏页上，坐标算出负数

`display:none` 的元素 `getBoundingClientRect()` 全为 0，相对位移是负数。

**实测**：光标被甩到 `(-336, -120)`。

**正确**：三道保护（见 §3.3 的 `moveTo`）。

### 5.8 无交互的页面，光标停在空白处

屏幕上出现光标，就意味着「这里可以点」。没有可点元素的画面要隐藏：

```js
cur.click(tl, agreeBtn, ">");
cur.hide(tl, ">+0.2");
go(tl, p6, p7, ">");
```

### 5.9 对字符串位置做算术

见 §3.3（`go()` 的写法）。

### 5.10 `display:flex` 盖掉 `display:none`

见 §3.4（页容器上不许写 `display`）。

### 5.11 GSAP `from()` 与紧随的空补间冲突

**错误**：

```js
tl.call(() => { box.style.display = ""; }, null, ">+0.2");
tl.from(box, { opacity: 0, duration: 0.25 }, "<");
```

`from()` 依赖「记录当前值再回到原值」。`display` 刚改成 `""`，同一时刻又有空补间，渲染时机被打乱，停在 `opacity: 0`。

**正确**：显式设初值 + `fromTo`。

```js
tl.call(() => { box.style.display = ""; box.style.opacity = "1"; }, null, ">+0.2");
tl.fromTo(box, { opacity: 0, y: -4 }, { opacity: 1, y: 0, duration: 0.28 }, "<");
```

**同族问题**：`fromTo` 的起始帧被后续补间吃掉，停在中间值。加 `immediateRender: false`。

```js
tl.fromTo(badge, { scale: 0.55 }, { scale: 1, duration: 0.4, immediateRender: false }, "<");
```

### 5.12 位移用 `left/top` 而不是 `transform`

`left/top` 每帧触发**布局重算**。用 `transform: translate()`：

```css
.cursor { left: 0; top: 0; will-change: transform; }
```

```js
el.style.transform = `translate(${x}px, ${y}px)`;
```

### 5.13 z-index 约定

```text
场景提示条  30
⋯ 菜单      70
光标        80   ← 必须在最上层
```

写死 `9999` 会让后续加元素时无法控制层级。

## 7. 界面细节

### 7.1 顶部状态栏不画

演示不需要模拟时间、信号、电池。去掉后内容区多出约 20px。

**注意**：删 JS 后要同步删 CSS，并确认导航栏、底部 tab 的选择器还在。

### 7.2 输入过程要逐字演

**错误**：点一下输入框，直接填入完整值。

**正确**：

```text
点输入框 → 键盘升起 → 逐字打出（每字 0.3~0.4 秒）
→ 弹出建议列表 → 点第一条 → 键盘落下
```

建议列表要**白底不透明**，钉在输入行正下方：

```css
.suggest {
  position: absolute;
  left: 14px; right: 14px;
  top: 176px;        /* 钉在输入行下方 */
  z-index: 90;
  background: #fff;
}
```

**坑**：若所有表单行都设了 `z-index: 2`，它们平级、后来居上，会把绝对定位的建议列表压在下面，看起来是「半透明」。只给目标行提升层级。

### 7.3 日期/时间选择要演两步

用户要看到「开始」与「结束」分别怎么选：

1. 点开始日期 → 焦点转到结束日期（右格变色）
2. 点结束日期 → 回填，滚轮高亮跟着变
3. 点确定 → 表单显示完整区间

需要两个控制函数：`setWheelActive(col, idx)` 与 `setEndFocus(onEnd)`。

### 7.4 确认类流程要两次点击

**错误**：点一次就显示「处理中…」。

**正确**：

| 时刻 | 动作 |
|---|---|
| 4s | 列表出现 |
| 6s | **点「导入」** → 密码栏展开，按钮仍是「开始导入」 |
| 7–8s | **逐字输入密码** |
| 9–10s | 停住，让「开始导入」可点状态被看清 |
| 11s | **点「开始导入」** → 按钮变「处理中…」 |
| 14s | 列表消失，输出结果 |

### 7.5 时长参考

| 段落 | 时长 |
|---|---|
| 单屏静态展示 | 1.5–2.5 秒 |
| 一次点击 + 反馈 | 0.8–1.2 秒 |
| 逐字输入（10 字） | 1.5 秒 |
| 结果停留 | 2–2.5 秒（要能读完） |
| 整个场景 | 8–20 秒 |

**太快等于没演**。观众要能读完每一行字。

## 8. 配色与设计规范

### 8.1 与你的主界面同一套 token

演示面板不要用深色霓虹（荧光绿 + 纯黑），除非你的产品本来就是那个风格。默认做法是**复用主界面的 CSS 变量**：

```css
.demo-panel {
  --d-bg:      var(--bg);
  --d-surface: var(--panel);
  --d-ink:     var(--ink);
  --d-muted:   var(--muted);
  --d-line:    var(--line);
  --d-accent:  var(--accent);
  --d-radius:  6px;
  --d-ease:    cubic-bezier(0.23, 1, 0.32, 1);
}
```

### 8.2 未定义的 CSS 变量会静默失败

```css
background: var(--d-surface);   /* 变量不存在 → 透明，不报错 */
```

**改配色前先确认变量存在**：

```bash
grep -c -- "--d-surface" demo.css
```

### 8.3 不要用的装饰

| 不要 | 原因 |
|---|---|
| 装饰性网格线（`repeating-linear-gradient`） | 纯装饰，无信息 |
| 四角 L 形标记 | 同上 |
| 扫描光 sweep | 霓虹感，与多数产品不符 |
| 列表项 `border-left: 2px` 色条 | 侧边色条是最典型的 AI 装饰 |
| `letter-spacing: .08em` 小字距堆叠 | eyebrow 式语法 |
| 纯黑阴影、模糊 80px | 阴影要染背景色相，模糊 ≤ 64px |
| 圆角混用（3px / 直角 / 12px） | 一套圆角系统，卡片 ≤ 16px |

### 8.4 `:not()` 累加的特异性陷阱

如果你的项目里有一条通用按钮规则，像这样：

```css
button:not(.link):not(.icon):not(nav button):not(.seg button):not(.tab):... {
  background: var(--panel);
  color: var(--ink);
}
```

**十几个 `:not()` 累加后，特异性远超 `.my-button`（0,1,0）**。你的样式会失效，且很难查。

**正确修法**：把目标类加进排除列表。

```css
button:not(...):not(.my-button) { ... }
```

**不要用 `!important` 硬压**：它会掩盖问题，后续更难维护。

**排查脚本**（注意第一个判断，写错会永远返回空）：

```js
const btn = document.querySelector(".my-button");
for (const sheet of document.styleSheets) {
  let rules; try { rules = sheet.cssRules; } catch { continue; }
  const walk = (list) => {
    for (const r of list) {
      // 只有分组规则才递归；CSSStyleRule 在某些引擎里 cssRules 是空列表
      if (!r.selectorText && r.cssRules) { walk(r.cssRules); continue; }
      if (!r.selectorText) continue;
      for (const sel of r.selectorText.split(",")) {
        try { if (btn.matches(sel.trim())) console.log(sel, r.style.background, r.style.color); } catch {}
      }
    }
  };
  walk(rules);
}
```

### 8.5 同名类被两份 CSS 覆盖

若演示样式与应用样式都定义了 `.demo-open`，且演示 CSS **后加载**，它会赢。

**修法**：给演示样式加作用域前缀。

```css
.demo-panel .demo-open { ... }
```

**隔离验证**：逐个禁用样式表，看哪个影响目标元素。

```js
for (const s of document.styleSheets) {
  s.disabled = true;
  console.log(s.href, getComputedStyle(btn).backgroundColor);
  s.disabled = false;
}
```

## 9. 进度与交互

### 9.1 自动播放与清单切换

`stage.js` 已经把进度条绑在 timeline 上（`fromTo` 挂在 `at: 0`）。清单点击直接 `stage.show(key)`。

### 9.1.1 要不要循环播放

**默认不循环**，播完就停在最后一帧。这是有意的：观众看完能停住读结果。

需要循环时，在 `stage.js` 的 `show()` 末尾加：

```js
tl = gsap.timeline({ paused: true, repeat: -1, repeatDelay: 1.5 });
```

**`repeat: -1` 的两个副作用，必须一起处理**：

| 副作用 | 处理 |
|---|---|
| 进度条只走第一遍 | 进度条的 `fromTo` 也要 `repeat: -1` + 相同 `repeatDelay`，否则第二遍进度条不动 |
| 光标停在最后位置 | 每遍开头要 `cur.show()`，否则第二遍没有光标 |

```js
const tl2 = gsap.timeline({ repeat: -1, repeatDelay: 1.5 });
barTween = tl2.fromTo(barFill,
  { scaleX: 0 }, { scaleX: 1, duration: total, ease: "none", repeat: -1, repeatDelay: 1.5 }, 0);
```

**验证时注意**：`verify.js` 的 `--seconds` 必须覆盖至少一遍完整时长，
否则后面的屏永远等不到。循环的场景建议 `--seconds` ≥ 一遍时长 × 1.5。

### 9.2 页面隐藏时暂停

```js
document.addEventListener("visibilitychange", () => {
  if (document.hidden) stage.pause();
  else stage.resume();
});
```

### 9.3 减少动效

```css
@media (prefers-reduced-motion: reduce) {
  .stage-screen *, .stage-screen *::before, .stage-screen *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

在 JS 里也可以判断并跳过非必要动画：

```js
const reduced = window.matchMedia("(prefers-reduced-motion: reduce)").matches;
if (!reduced) tl.from(card, { y: 12, opacity: 0, duration: 0.35 }, 0.1);
```

## 10. 验收

### 10.1 光标必须逐项核对

临时打日志，确认每个落点都在元素中心：

```js
toAt(tl, target, opts = {}) {
  tl.call(() => {
    const p = moveTo(target);
    console.log("[toAt]", target.className, p ? `${Math.round(p.x)},${Math.round(p.y)}` : "SKIP");
    ...
  }, null, opts.at ?? ">");
}
```

期望形如：

```text
[toAt] row              280,155
[toAt] nav-right        419,49
[toAt] menu-item        374,108
[toAt] choice           280,254
[toAt] formrow is-email 280,189
```

### 10.2 两次 toAt 落在同一坐标是正常的

如果两屏的目标元素恰好在相同位置（都是页首第一行），`[toAt]` 会打印两次相同数字。这不是 bug，但会让人误判成「光标没动」。

**写示例或自检时，让不同屏的目标位置错开**：

```js
const p2 = createPage(shell);
row(p2, "零钱");
row(p2, "银行卡");
const walletRow = row(p2, "账单");   // 第三行，坐标与第一页不同
```

### 10.3 验证时必须换算坐标系

**这是验证时最容易骗自己的地方。**

`dot.getBoundingClientRect()` 返回的是**屏幕坐标**，而 `toAt` 打印的是**画布坐标**（0–560 / 0–700）。直接用前者去比，会误判成「光标没动」。

```js
const screen = document.querySelector(".stage-screen");
const sr = screen.getBoundingClientRect();
const sc = sr.width / 560;                    // 当前缩放比

const canvasX = (r.left + r.width / 2 - sr.left) / sc;
const canvasY = (r.top + r.height / 2 - sr.top) / sc;
```

**判据**：`canvasX/canvasY` 要与 `[toAt]` 打印的数字一致（误差 ≤2px）。

实测对照：

```text
[toAt] d-btn 105,157
canvasX: 105, canvasY: 157     ✓ 一致
```

### 10.4 逐秒采样状态

```js
for (let i = 0; i < 12; i += 1) {
  const s = await page.evaluate(() => {
    const cur = document.querySelector(".d-cursor");
    const dot = document.querySelector(".d-cursor-dot");
    const r = dot.getBoundingClientRect();
    return {
      visible: Number(getComputedStyle(cur).opacity) > 0.05,
      x: Math.round(r.left + r.width / 2),
      y: Math.round(r.top + r.height / 2),
    };
  });
  console.log(i + "s", s);
  await new Promise((r) => setTimeout(r, 1000));
}
```

**判据**：

- 坐标要在变（不是卡住不动）
- 每一帧都落在画布范围内
- 无交互的页面 `visible: false`

### 10.5 视觉比对：必须把图读进来，不能凭记忆

断言只能查「有没有」。**「像不像」必须靠看图**，而这件事 AI 做得到：只要流程里明确要求它读。

#### 10.5.0.1 三步闭环（缺一不可）

```text
1 读录屏帧      → 用 read 工具打开 PNG，实际看图，逐项写下你看到的
2 实现并截图    → 用 puppeteer 截 .stage-screen 区域（不是整页）
3 读自己的截图  → 再用 read 打开，与第 1 步的清单逐项对照，列出差异
```

**第 1 步和第 3 步必须是「read 工具看图」，不能是「我记得应该是」**。
只看文件名、只看代码、只看 DOM，都不算看过。

#### 10.5.0.2 选帧：先排除过渡帧

规则与 §1.4.2 相同，此处只列判据。**核心：没有至少一行完整内容的帧不能当基准。**

抽出的帧里有大量无效帧。**先看图判断它是不是完整界面**：

| 不该用来做基准的帧 | 特征 |
|---|---|
| 加载中 | 只有 `✕` + 进度条，内容区空白 |
| 刷新中 | 整片白或灰 |
| 转场中 | 两个界面叠在一起 |
| 黑屏 | 系统遮挡提示 |

**判据**：这一帧里有没有**至少一行完整的内容**（图标 + 文字 + 右侧值）。
没有就换下一帧。

> 实测踩过：拿第 10 秒的帧做基准，那张只有 `✕` 和进度条，
> 内容区全白。用它对比等于用空白当标准。
>
> 更糟的是：审查者会把「实现里有内容」判成错误，因为基准是空的。
> 那一轮出的差异表 13 项全是 ✗，一项不可用。

**读图能发现断言永远查不出的东西**（本次真实案例）：

同一屏「钱包」，我的实现 `verify.js` 判**全部通过**（文案齐全、iconLike 6 ≥ 6、
mutedText 5 ≥ 2、无 JS 错误），但读图审查发现四处结构错误：

| 项 | 真机录屏 | 我的实现 | 断言能查吗 |
|---|---|---|---|
| 分组 | **4 组**：3 行 / 2 行 / 1 行 / 4 行 | 2 组：5 行 + 1 行 | ✗ 查不出 |
| 缺失行 | 有「支付分 / 支付设置 / 身份信息 / 客服中心」 | 完全没有 | ✗ 文案里没要求就查不出 |
| 左侧竖条 | 绿色 `#27AE65`，x≈6–22，只覆盖第一组 | 没有 | ✗ 查不出 |
| 右侧箭头 | **没有** | 每行都画了 | ✗ 查不出 |

**这就是「断言通过 ≠ 复刻到位」的实例。** 断言只保证「你要求的元素都在」，
保证不了「你的结构对」。

**一次实测的读图报告精度**（说明这条路可行）：

```text
导航栏左控件：✕（x≈9–25，y≈43–55）
导航栏右控件：•••（x≈292–306，y≈47–52）
进度条：绿色 #00be61，宽 31/320（约 10%）
正文：纯白 #fdfdfd，零行内容
```

**AI 能给到像素坐标与精确色值**，不是模糊描述。这说明「读图比对」不是安慰剂，
是真能落地的手段。

#### 10.5.0.3 读图结论必须用像素数据校验

**读图会出错，而且错得不一致。** 实测两次审查同一张基准帧，给出互相矛盾的结论：

| 审查者 | 结论 |
|---|---|
| 第一次 | **4 组**（3 / 2 / 1 / 4 行） |
| 第二次 | **2 组**（各 5 行） |

用像素分析一验，第二次对：这张图就是 **2 张白卡、每张 5 行**。

##### 一个完整的翻车过程（照抄这个教训）

这一屏「钱包」，三方给出的结论全不一样：

| 来源 | 结论 |
|---|---|
| 审查 AI #1 | **4 组**：3 / 2 / 1 / 4 行 |
| 审查 AI #2 | **2 组**：各 5 行 |
| 我的实现 | 按 #1 做了 4 组 |
| **像素分析** | **3 张卡：5 / 1 / 4 行，共 10 行** |

**三个都不对。** 只有像素分析是对的，而且它还能继续往下查：

```text
卡1 (y=70..300, 高231px): 5 行   y=87,133,180,226,273
卡2 (y=311..356, 高46px):  1 行   y=328          ← 只有「分付」一行
卡3 (y=366..551, 高186px): 4 行   y=384,430,476,523
```

**继续往下查还能纠出更多错**。裁出 10 条行图逐条读：

| 我原来写的 | 实际 |
|---|---|
| 每行都没有右侧箭头 | **每行都有** `›` |
| 副标题是灰色 | 「收益率0.85%」「买新品手机享24期免息」是**橙色** |
| 左侧有绿色竖条 `#27AE65` | 有，但是**浅灰**的，且只在「分付」行左边 |
| 零钱图标是圆形实心 | 黄色**环形**，白底 |
| 经营账户是方形 | 方形**带圆圈** |

**教训**：

1. **读图结论必须用像素验证数量**（组数、行数），两者冲突时以像素为准
2. **颜色必须取色值**，不能靠描述（「灰色」和「橙色」差别很大）
3. **有没有箭头、有没有竖条**这类二元判断，要么裁图看，要么扫像素，不能凭印象

**结论：读图给的是「初稿」，像素给的是「判决」。数字类断言必须用代码验证。**

##### 怎么校验（三条命令级操作）

> **先说这个坑**：最直觉的做法「按亮度阈值切白卡」是**错的**。
> 行与行之间也有 1px 浅缝（lum ≈ 246），会被误判成卡片边界，
> 一张卡被切成好几段。实测按阈值切，把 3 张卡切成了 6 段。

**1 数白卡（分组数）**：判据不是「这一行亮不亮」，而是「**整行大部分是不是页面灰底**」。

```python
from PIL import Image
import numpy as np

a = np.array(Image.open("s_005.png").convert("RGB")).astype(int)
h, w, _ = a.shape

GRAY_LO, GRAY_HI = 228, 242      # 页面灰底 #ececec 附近

def is_gap_row(y):
    row = a[y, :, :].mean(axis=1)
    near_gray = np.sum((row >= GRAY_LO) & (row <= GRAY_HI))
    return near_gray > w * 0.8    # 超过 80% 宽度是灰底

# 合并连续 gap 行 -> 卡间空隙
gaps = [y for y in range(h) if is_gap_row(y)]
runs = []
for y in gaps:
    if runs and y - runs[-1][-1] <= 1:
        runs[-1].append(y)
    else:
        runs.append([y])
runs = [(r[0], r[-1]) for r in runs if len(r) >= 3]

# 两个空隙之间就是一张卡
cards = []
for i in range(len(runs) - 1):
    y0, y1 = runs[i][1] + 1, runs[i + 1][0] - 1
    if y1 - y0 > 40:              # 太矮的不是卡
        cards.append((y0, y1))

print("卡间灰缝:", runs)
print("白卡:", cards, "共", len(cards), "张")
```

实测输出（这张图）：

```text
卡间灰缝: [(31,69), (301,310), (357,365), (552,733)]
白卡: [(70,300), (311,356), (366,551)] 共 3 张
```

**注意 (31,69) 和 (552,733) 是导航栏与底部留白**，不是卡间缝。真正的卡间缝只有
`(301,310)` 和 `(357,365)`，都是 9–10px。

**2 数行（每卡几行）**：在卡内找「文字行」——高度 ≥ 6px 的暗区。
1–2px 的暗区是行分隔线，要排除。

```python
def rows_in_card(a, y0, y1, x0=40, x1=300):
    ys = [y for y in range(y0, y1 + 1) if a[y, x0:x1].mean() < 250.5]
    groups = []
    for y in ys:
        if groups and y - groups[-1][-1] <= 2:
            groups[-1].append(y)
        else:
            groups.append([y])
    # 只要高度 >= 6px 的，1-2px 是分隔线
    return [(g[0], g[-1]) for g in groups if g[-1] - g[0] + 1 >= 6]

for i, (y0, y1) in enumerate(cards, 1):
    rs = rows_in_card(a, y0 + 2, y1 - 2)
    print(f"卡{i}: {len(rs)} 行  {rs}")
```

实测输出：

```text
卡1: 5 行  [(87,98) (133,145) (180,191) (226,238) (273,284)]
卡2: 1 行  [(328,340)]
卡3: 4 行  [(384,395) (430,442) (476,488) (523,535)]
合计 10 行
```

**「≥ 6px 才算一行」这个阈值不能省**：不排除分隔线的话，每张卡的行数会翻倍。

**3 数颜色（图标色数）**：把非白非灰像素按色相分组。

```python
import colorsys
hues = {}
for y in range(70, 551, 4):
    for x in range(20, 60, 2):
        r, g, b = a[y, x] / 255
        hh, ss, vv = colorsys.rgb_to_hsv(r, g, b)
        if ss > 0.25 and vv > 0.3:          # 有彩色
            hues.setdefault(round(hh * 12) / 12, 0)
            hues[round(hh * 12) / 12] += 1
print(sorted(hues, key=hues.get, reverse=True))
```

##### 什么时候必须校验

| 结论 | 必须校验 | 原因 |
|---|---|---|
| 有几组 | ✓ | 卡片边界靠亮度判断，肉眼容易把行分隔线当成分组线 |
| 每行几行 | ✓ | 行数多时容易数错，尤其有滚动残留 |
| 有几个图标 | ✓ | 相似形状容易混 |
| 图标是红绿蓝 | 建议 | 色值容易受抗锯齿影响 |
| 文案写了什么 | ✗ | 像素分析帮不上，只能读图 |
| 布局好不好看 | ✗ | 主观判断 |

**规则**：凡是能数出来的，都用代码数一遍。数出来的才写进 `screens.json` 的 `minStats`。

##### 像素校验也有止境（实测踩过）

**它同样会无限进行下去。** 实测一个 AI 在「像素核对竖条/分隔线/图标色/几何」
这一步待了 13 分钟，**一个文件都没写**。

**用 `frame-crop.py` 的话，像素部分已经全部做完了，不要再自己量：**

```bash
python frame-crop.py base.png --outdir crops
# 3 秒输出：
#   卡片 3 张，行 10 行，箭头 10 个
#   颜色 5 种：黄、绿、青、蓝、橙
#   summary.json 里有每张卡的 y0/y1、每行的 y 中心
```

**`summary.json` 里已有的，一律不要再测**：

| 已提供 | 字段 |
|---|---|
| 卡片数与边界 | `cards[].y0` / `cards[].y1` |
| 每卡行数与行位置 | `cards[].rows[].y` |
| 箭头总数 | `totals.chevrons` |
| 图标主色 | `colors[].bucket` / `colors[].hex` |

**硬性上限**：像素校验阶段最多 **5 分钟**。超过说明你在重复测量
`summary.json` 里已有的数据。

**只测 `summary.json` 里没有的**，例如：

- 左侧竖条是否存在（`rails` 指标在 `verify.js` 里有，但基准帧要自己看）
- 行内元素的水平位置（图标 x、文字 x、右侧值 x）
- 分组之间是灰缝还是细线

这些看完记下来就够，不要追到像素级。

##### 两个审查者结论不一致时怎么办

**不要取平均值，不要投票。用像素裁决。**

```text
A 说 4 组，B 说 2 组
→ 跑一次亮度扫描
→ 输出几段 white 就是几组
→ 谁对用结果，另一方的结论作废
```

**这次我犯了错**：先信了 A 的「4 组」，按它重写了钱包页，做了 4 张卡。
实际上就是 2 张卡各 5 行。返工一次。

#### 10.5.0.6 子 agent 审查能做什么、不能做什么

用另一个 AI 做审查**是可行的**，但要限定它的工作：

| 能做 | 不能做 |
|---|---|
| 读两张图，逐项列出可见差异 | 判断「哪种更好看」 |
| 数行数、认元素、比颜色 | 判断间距是 12px 还是 14px |
| 指出「少了 4 行」「缺左侧竖条」 | 判断动画节奏对不对 |

**限制它的输出格式**，否则会写一堆分析而没有结论：

```text
【基准图实际内容】
【待审图实际内容】
【差异表】| 项 | 基准 | 待审 | 一致? |
【必须修的项】
```

要求它「实际看图，不要猜」。审查者一旦开始推测，结论就不可用。

### 10.6 断言式验收：让「偷懒」变成机器可判定的失败

**光在文档里写「要有图标」是管不住的。** 实测过一个零记忆 AI：文档明写「图标/副标题/右侧值一个都不能省」，
它照样只画文字 + 箭头。

**唯一有效的机制是断言**：把期望值写成数据，让脚本判定，失败就退出码 1。

#### 10.6.1 脚本

完整脚本见 `docs/reference/assets/verify.js`（在本文档同级的 `assets/` 下）。
复制到你的项目，改三个参数即可。

```bash
node verify.js \
  --url http://127.0.0.1:8899/index.html \
  --spec ./screens.json \
  --scene 场景key \
  --seconds 8
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--url` | `http://127.0.0.1:8899/index.html` | 演示页地址 |
| `--spec` | `./screens.json` | 屏清单；缺省时只跑基础三项 |
| `--scene` | 无 | 有左侧清单时先点这项。**匹配规则**：按钮的 `textContent` 或 `dataset.key` 与参数完全相等。用中文名做 key 时按钮文字必须与 key 一致，否则找不到（会打印提示并按默认场景继续） |
| `--seconds` | `20` | 逐秒采样时长。**必须覆盖至少一遍完整时长**，否则后面的屏等不到 |
| `--chrome` | Chrome 默认路径 | 浏览器可执行文件 |
| `--puppeteer` | 本机 puppeteer-core | 用于 `import` |

#### 10.6.2 自动阈值：不用手写 screens.json

`frame-crop.py` 已经把基准帧的结构数出来了，`verify.js` 可以直接读它，
**自动生成阈值**：

```bash
# 1 切基准帧（3 秒）
python frame-crop.py base.png --outdir crops/

# 2 自动比对（不需要 screens.json）
node verify.js \
  --url http://127.0.0.1:8899/index.html \
  --from-scan crops/summary.json \
  --report-only          # 只看差多少，不判失败
```

**它自动推导的阈值**：

| 基准帧数据 | 推导出的断言 |
|---|---|
| `totals.rows` | `rows ≥ 基准行数` |
| `totals.chevrons` | `chevrons ≥ 基准箭头数` |
| `colors.length` | `colored ≥ 颜色种类数` |
| `totals.rows - totals.cards` | `dividersH ≥ 行数 - 卡片数`（每卡至少留一条分隔线） |

**实测效果**（拿一个已知有错的钱包页实现去跑）：

```text
[全屏]
  ✓ colored = 6（≥ 5）
  ✗ rows 只有 8，要求 ≥ 10
  ✗ chevrons 只有 6，要求 ≥ 10
  ✗ dividersH 只有 6，要求 ≥ 7

差异 4 项（--report-only，不判失败）
```

**三条差异全是真的**：那个实现只画了 6 行（漏了 4 行），箭头只有 6 个，
分隔线少一条。**这些之前靠人眼比对全都漏掉了。**

**`--report-only` 的用途**：开发过程中先看差多少，不阻断。
定稿时去掉这个参数，用退出码卡 CI。

**自动模式覆盖不到的部分**：文案（`mustContain`）仍需人写，
因为它要靠读图得到，像素分析认不出字。

#### 10.6.3 手写 screens.json（需要精确控制时）

这是**唯一能防偷懒的产物**。不是「记在脑子里」，是写成文件。

```json
{
  "cursor": true,
  "screens": [
    {
      "name": "钱包页",
      "expectText": "零钱",
      "mustContain": ["零钱", "经营账户", "零钱通", "银行卡", "亲属卡", "分付", "收益率"],
      "minStats": { "iconLike": 6, "mutedText": 2 },
      "timeout": 8000
    }
  ]
}
```

| 字段 | 作用 |
|---|---|
| `cursor` | 本场景是否该有光标。纯展示页写 `false` |
| `expectText` | 这段文案出现的那一帧，立即对该屏断言（不是等到最后） |
| `mustContain` | 这一屏必须出现的所有文案，缺一条就失败 |
| `minStats.iconLike` | 有背景色的方块数量下限（图标的机器判据） |
| `minStats.mutedText` | 小于等于 12px 的文字数量下限（副标题的机器判据） |
| `minCount` | 用 CSS 选择器直接数元素，如 `{ ".row": 5 }`。**项目自定义**，换项目改这里 |
| `assert` | JS 表达式数组，每条必须为真，如 `["document.querySelectorAll('.card').length === 3"]`。最灵活也最易写错 |

#### 10.6.3.1 哪些是通用的，哪些是固定的

**通用（脚本内置，换项目不用改）**：只用几何尺寸与计算样式判断，不依赖任何类名。

| 指标 | 判据 | 能查出什么 |
|---|---|---|
| `iconLike` | 16–64px 且有非透明背景色 | 有没有画图标 |
| `mutedText` | 字号 ≤ 12px 且在页面左侧 60% 区域内的文字叶子 | 有没有副标题（**不含右侧金额**） |
| `chevrons` | 文字内容为 `›` / `>` / `»` / `→` | 有没有右侧箭头 |
| `clickables` | `button` / `role=button` / `cursor:pointer` | 有几处可点 |
| `dividersH` | 高 ≤2px 且宽 >100px | 有没有行分隔线 |
| `rails` | 宽 ≤6px 且高 >20px 且有底色 | 有没有左侧竖条 |
| `colored` | 背景色饱和度 >0.25 | 有几个彩色元素 |
| `rows` | 按 y 坐标聚类文字（4px 一档，间隔 >8px 算新行） | 页面内的文字行数（**不含导航栏**） |

**固定（要按项目写）**：

| 项 | 为什么必须自定义 |
|---|---|
| `mustContain` 文案 | 每个产品的文字都不同 |
| `minStats` 的具体数值 | 「至少 3 个图标」是你的产品决定的，不是通用的 |
| `minCount` 选择器 | 类名每个项目都不一样 |
| `assert` 表达式 | 业务规则各不相同 |

**三个指标的口径要记清**（实测踩过，口径不明会让阈值靠试跑反推）：

| 指标 | 统计范围 | 排除什么 |
|---|---|---|
| `mutedText` | 页面内、左侧 60% 宽度、字号 ≤12px | 右侧金额（金额也在右但不算副标题） |
| `rows` | 页面内的文字叶子，按 y 聚类 | 导航栏、状态栏（它们在页容器外） |
| `iconLike` | 16–64px 且有底色/描边/内部内容的元素 | 大色块、纯文本 |

**一句话**：**度量方式通用，阈值和文案固定。**

**换项目时只改 `screens.json`，不改 `verify.js`。**

#### 10.6.3.2 三个层次的取舍

| 方案 | 优点 | 缺点 | 用在哪 |
|---|---|---|---|
| 只内置固定指标 | 零配置 | 换项目查不出新东西 | 起步 |
| 内置通用指标 + spec 阈值 | 换项目只改 JSON | 指标准确度有限（如 `iconLike` 按尺寸猜，圆形徽标也算） | **推荐** |
| 加 `minCount` 自定义选择器 | 精确 | 要维护选择器 | 关键结构 |
| 加 `assert` 任意表达式 | 最灵活 | 容易写错，难调试 | 兜底 |

**先用前两层。** 只有通用指标判断不了「这张卡里必须正好 5 行」这种精确结构时，才用 `minCount`。

#### 10.6.4 三条基础断言（无需 spec）

| 检查 | 判据 |
|---|---|
| 页面叠加 | 任意时刻不能连续 3 秒显示 2 页（切页的 `display:none` 没执行） |
| 光标 | 坐标必须在画布内；必须停过 ≥2 个不同位置 |
| JS 错误 | `pageerror` 与 `console.error` 为 0 |

#### 10.6.5 多屏演示的两条硬约束

**约束 1：每屏必须在 `--seconds` 内至少出现一次。**

`verify.js` 只在指定时长内采样。若你的场景单屏停留 5 秒，而 `--seconds 8`，
第二屏可能还没出现就结束了，会被判「整场都没等到」。多屏时要么加长
`--seconds`，要么压缩单屏时长。

**约束 2：不要让隐藏页的文字还留在 DOM 里。**

`verify.js` 用「可见页的 textContent」判断当前是哪一屏。如果隐藏页只是
`opacity: 0` 或 `visibility: hidden`，文字仍在 DOM 里，会被误判成「这一屏已出现」。

**必须用 `display: none` 隐藏**（本档 §3.3 的 `go()` 就是这么写的）。
若你改成了 `opacity: 0`，断言会提前命中，导致后续所有检查错位。

**为什么必须「那一屏出现时就断言」**：脚本会重播一次，在 `expectText` 出现的
那一帧检查。如果等整段播完再查，前面的屏已经 `display:none`，`textContent` 是空的，
会误报「缺少文案」。这个坑实测踩过。

#### 10.6.6 实测对照（这就是机制有效的证据）

**偷懒版**（只有文字 + 箭头）：

```
✗ iconLike 只有 0，要求 ≥ 3
判定：不通过
```

**正确版**（照录屏画了六个彩色图标 + 副标题）：

```
✓ 文案齐全（7 项）
✓ iconLike = 6（≥ 6）
✓ mutedText = 5（≥ 2）
判定：全部通过
```

#### 10.6.7 三种机制的分工

| 机制 | 管什么 | 局限 | 该用在哪 |
|---|---|---|---|
| 文档写「必须画图标」 | 只能提醒 | **AI 会忽略**（已实测） | 仅作说明 |
| **断言脚本** | 「有没有」：元素数量、文案、切页、错误 | 查不出「像不像」 | **每次提交都跑，CI 拦** |
| **子 agent 读图比对** | 「像不像」：少了哪几行、缺哪个元素、颜色对不对 | 判断力不稳定；慢（十几分钟） | **每屏做完跑一次，改到差异表全 ✓** |

**实测成本**（本次会话数据）：

| 机制 | 单次耗时 | 失败模式 |
|---|---|---|
| 断言脚本 | 30–60 秒 | 结果确定，失败信息精确到元素 |
| 子 agent 读图 | **9–23 分钟** | 容易卡在「整理结论」；需要限制输出格式 |

读图慢是因为**它真的在做视觉分析**：会裁图、数行、认元素、比颜色。
这不是浪费，是它唯一能发现结构差异的方式。

**结论：两个都要用，不是二选一。**

- 断言是**闸门**：成本低、结果确定、能自动化，挡住「偷懒」这一类问题。
- 读图是**镜子**：成本高、需要判断力，但只有它能发现「少画了四行」「缺左侧竖条」这种结构差异。

**顺序**：先读图把结构改对，再跑断言确认没退化。反过来做会反复返工。

**读图这一步的关键**（实测得出的三条）：

1. 必须用 `read` 工具真的打开 PNG，不能凭代码或 DOM 推断
2. 基准帧必须选**有完整内容的帧**，不能是加载中/转场中的帧
3. 审查者的输出格式要限制死，否则会写一堆分析而没有结论

## 11. 迁移到你的项目

### 11.0 换项目时必须改的清单

把这份文档和脚本拿到新项目前，先过一遍这张表。**表里没列出的一律不用改。**

| 项 | 在哪 | 改成什么 |
|---|---|---|
| `$FFDIR` | §2.1 装 ffmpeg 那段，bash 里首次设置 | 你机器上 ffmpeg 的 bin 目录 |
| `$TOOLS` | §2.1 的 PowerShell 段 | 你放工具的根目录 |
| `SCREEN_W` / `SCREEN_H` | `stage.js` 顶部 | 你的画布尺寸，三处同步（见 §2.7） |
| `.stage-screen` 宽高 + `aspect-ratio` | `demo.css` | 同上，两处一致 |
| 外壳 `createShell` | `scenes/*.js` | 你的产品外壳（手机壳 / 浏览器框 / 桌面窗口） |
| 配色 token | `demo.css` | 复用你主界面的 CSS 变量 |
| `screens.json` | 项目根 | 你的屏清单：文案、基准帧、阈值 |
| `--puppeteer` 或 `PUPPETEER_CORE` | 命令行/环境变量 | 你的 puppeteer-core 路径；项目里装了 `puppeteer-core` 可省略 |
| `--chrome` 或 `CHROME_PATH` | 命令行/环境变量 | 通常不用给，脚本会自动探测常见位置 |

**以下不用改**（脚本与积木层与业务无关）：

- `verify.js` 的度量逻辑（8 项通用指标）
- `kit.js` 的 `cursor` / `type` / `ok`
- `go()` 的写法
- `stage.js` 的缩放与播放控制

### 11.1 要改的

| 项 | 怎么改 |
|---|---|
| `SCREEN_W/H` | **取基准帧的宽高比**，同比放大 1 或 2 倍（见 §2.7.1）。不要套用示例里的 560×700 |
| 外壳 | 按你的产品做（手机壳 / 浏览器框 / 桌面窗口） |
| 配色 token | 复用你主界面的 CSS 变量 |
| 场景内容 | 按你的录屏一屏屏写 |

### 11.2 不用改的

| 项 | 为什么 |
|---|---|
| `stage.js` 全部 | 缩放、播放、进度与产品无关 |
| `kit.js` 的 `cursor` | 含三道保护，是通用逻辑 |
| `kit.js` 的 `type` / `ok` | 逐字打印与成功印章是通用件 |
| `go()` 的写法 | 只依赖 GSAP 的位置参数语义 |

### 11.3 目录名可以不同，`demo/` 只是建议

§0.0 写的是 `demo/`，那是建议结构。放哪里都行，只要：

- `stage.js` / `kit.js` / `demo.css` / `scenes/` 的相对位置不变
- `index.html` 里的 `import` 路径跟着改
- 起服务时把工作目录设成 `index.html` 所在目录

### 11.4 最容易漏的三件事

1. **尺寸三处同步**：`stage.js` 常量、`.stage-screen` 宽高、`.stage-box` 的 `aspect-ratio`
2. **页容器上不写 `display`**：写了就用内联 `none` 也藏不住
3. **光标坐标在 `tl.call` 里算**：构建时算必然偏
