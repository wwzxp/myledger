# 多用户与公网部署 · 产品规格

> 状态：草案（待实现）
> 生成方式：`to-spec` 综合本次会话共识，不做二次访谈
> 前置规格：`docs/specs/产品规格-我的账本工具.md`（单用户本地版，本规格在其上扩展）

## 问题陈述

现在的应用是**单人本地工具**：只监听 `127.0.0.1`，没有登录，数据表里也没有「这是谁的账」这个概念。三个具体障碍：

1. **手机上用不了**。页面为桌面布局设计，手机上侧栏占掉半屏、表格横向溢出、点击区过小。
2. **一出门就断了**。服务绑在回环地址，离开这台电脑就访问不到。
3. **不能多人共用**。即使把端口开放，所有人看到的是同一本账，无法区分「我的支出」与「家里的支出」；也没有任何鉴权，公网上任何人都能读写账本。

我要的是：把它放到一台 Linux 服务器上，手机浏览器打开一个网址、登录后即可用；每个用户只看到自己的账，而管理员能看到全部。

## 解决方案

在现有应用上加三层能力，**不改变已有的账单解析与分类逻辑**：

1. **多用户与权限**：每条账目、账户、分类规则都有归属人；普通用户只能读写信自己的数据，管理员可切换到「全部账本」查看与筛选。
2. **鉴权**：用户名 + 密码登录，服务端会话（HttpOnly + Secure + SameSite=Lax cookie，30 天滑动续期，可主动登出失效）。账号仅由管理员创建。
3. **移动端与公网可达**：响应式布局 + PWA（可加到主屏幕、全屏运行、静态资源缓存）；通过 Cloudflare Tunnel 暴露，HTTPS 由 Cloudflare 提供，服务器不开放任何入站端口。

现有数据库**清空重建**，不做历史数据迁移。

## 用户故事

### 登录与会话

1. 作为用户，我在手机浏览器打开网址时，看到登录页而不是账本内容。
2. 作为用户，我输错密码时看到「用户名或密码不正确」，而不是具体是哪一项错了。
3. 作为用户，我登录成功后进入自己的账本，刷新页面不需要重复登录。
4. 作为用户，我 30 天内再次打开时不需要重新登录（滑动续期）。
5. 作为用户，我点「退出登录」后，当前设备的会话立即失效。
6. 作为用户，我在另一台设备登录不会挤掉当前设备的会话。
7. 作为用户，我忘记密码时不能自助重置，需要管理员重置（单机小团队场景，避免引入邮件服务）。
8. 作为用户，我可以修改自己的密码，修改后其他设备上的会话仍然有效。

### 账号管理（管理员）

9. 作为管理员，我能在设置页看到所有用户列表（用户名、角色、创建时间）。
10. 作为管理员，我能创建用户并设置初始密码。
11. 作为管理员，我能重置某人的密码。
12. 作为管理员，我能把用户提升/降级为管理员，但**不能降级最后一个管理员**。
13. 作为管理员，我能禁用某个用户，禁用后其所有会话立即失效。
14. 作为管理员，我不能删除自己正在使用的账号。
15. 作为普通用户，我在界面上看不到用户管理入口。

### 数据隔离

16. 作为用户，我导入的账单只出现在我的账本里。
17. 作为用户，我看不到别人的账目、账户、分类规则。
18. 作为用户，我修改分类或确认账目时，只能影响自己的数据；即使猜到别人的记录 id 也无法操作。
19. 作为管理员，我默认看到自己的账本，可切换到「全部账本」查看所有人的汇总。
20. 作为管理员，在「全部账本」下我能按用户筛选，也能看到每笔账的归属人。
21. 作为管理员，我导入的账单归属我自己，不会自动分给别人。
22. 作为用户，同一笔交易被两个用户分别导入时，各自保留一份，互不去重（跨用户去重没有意义且有隐私风险）。

### 移动端

23. 作为手机用户，我能用单手完成「导入账单 → 看待确认 → 确认分类」这条主链路。
24. 作为手机用户，侧栏在窄屏下变成底部导航栏，不遮挡内容。
25. 作为手机用户，账单列表在窄屏下变成卡片式，不需要横向滚动。
26. 作为手机用户，所有可点击元素的触控区不小于 44×44 像素。
27. 作为手机用户，输入密码、金额时键盘类型正确（数字键盘/普通键盘）。
28. 作为手机用户，我把站点「添加到主屏幕」后，打开时全屏显示，没有浏览器地址栏。
29. 作为手机用户，我在弱网下再次打开时，页面骨架能快速显示而不是白屏。
30. 作为手机用户，我升级后不会因为缓存继续使用旧版页面（service worker 版本更新）。

### 部署与运维

31. 作为运维者，我用 `docker compose up -d` 一条命令启动服务。
32. 作为运维者，数据库与配置挂载在宿主机卷上，重建容器不丢数据。
33. 作为运维者，首次启动时如果没有任何用户，系统创建一个管理员账号并把初始密码打印到日志。
34. 作为运维者，服务监听容器内端口，宿主机不暴露该端口到公网。
35. 作为运维者，我通过 Cloudflare Tunnel 把域名指向该服务，不需要在服务器上配置证书。
36. 作为运维者，容器重启后会话仍然有效（session 持久化在数据库）。
37. 作为运维者，我能从日志里看到登录失败次数，便于判断是否被暴力破解。

### 安全边界

38. 作为用户，我的密码以加盐哈希存储，数据库泄漏也拿不到明文。
39. 作为用户，我的会话 cookie 带 `HttpOnly`、`Secure`、`SameSite=Lax`，前端脚本读不到。
40. 作为运维者，连续登录失败会被限流（同一用户名/IP 短时间内多次失败后暂时拒绝）。
41. 作为用户，所有写操作都校验当前用户对目标数据的归属，越权返回 404 而不是 403（不泄漏资源是否存在）。

## 实现决策

**数据模型**

- 新增 `users` 表：`id`、`username`（唯一）、`password_hash`、`role`（`admin` / `user`）、`disabled`、`created_at`。
- 新增 `sessions` 表：`token_hash`（不存明文 token）、`user_id`、`created_at`、`last_seen_at`、`expires_at`、`ua`。
- `entries`、`accounts`、`merchant_category_rules` 增加 `owner_id`，作为**必填外键**。
- 所有读取入口统一走一个「当前用户可见范围」参数：普通用户 = `owner_id = 自己`；管理员在「全部账本」模式 = 不加过滤。
- 清空重建：现有库整体废弃，新库由迁移脚本创建。

**鉴权**

- 密码哈希用标准库 `hashlib.scrypt`，参数写明在代码常量里（n=2^14, r=8, p=1），不引入 passlib/bcrypt 依赖。
- 登录成功生成 32 字节随机 token，**数据库只存其 SHA-256**；cookie 存明文 token。
- 会话 30 天，每次请求刷新 `last_seen_at` 与 `expires_at`（滑动续期）。
- 登出删除该会话行；禁用用户删除其全部会话行。
- 所有非静态路径统一走鉴权检查，未登录跳转登录页（页面）或返回 401（`/api/*`）。

**权限**

- 服务端在每个写接口执行归属校验，不依赖前端隐藏按钮。
- 归属不符一律返回 404，避免通过状态码探测他人资源是否存在。
- 管理员专属接口做角色检查（用户管理）。

**前端**

- CSS 断点：`<= 768px` 为手机布局（侧栏变底部导航），`769–1180px` 为平板，`> 1180px` 保持现状。
- PWA：`manifest.json`（名称、图标、`display: standalone`、主题色）+ `service-worker.js`（仅缓存静态资源，API 一律网络优先，避免读到旧账本）。
- service worker 用版本号命名缓存，激活时清理旧缓存。
- 新增登录页与用户管理页，沿用现有视觉。

**部署**

- `Dockerfile`：基于 `python:3.12-slim`，安装 `pyproject.toml` 声明的依赖。
- `docker-compose.yml`：`app` 服务（不映射端口到宿主机，只 `expose`）+ `cloudflared` 服务（用 `TUNNEL_TOKEN` 环境变量接入）。
- 数据卷：`./data`（SQLite）、`./config`（`myledger.toml`）。
- 首启动无用户时创建 `admin` 并打印随机初始密码到日志。

## 测试决策

**好测试的判据**：从 HTTP 层进入，断言「某个用户能看到/改到什么」。不断言 SQL 文本，不断言内部函数调用次数。

**测试边界**（两条并存，各管一段）：

- **HTTP 层（主）**：启动临时数据库 + 临时用户，用真实请求验证登录、会话、隔离、越权、admin 全量视图。
- **浏览器自动化（ego）**：验证登录表单实际可用、登出后回登录页、手机视口下导航变底部栏且主链路可点击、PWA manifest 可被浏览器识别。这类「人看得见」的问题，HTTP 层测不出来。
- **纯函数层**：密码哈希与校验、会话 token 生成与过期判断。
- **不测**：CSS 断点的具体像素值、manifest 的每个字段文本。

**必测的行为**：

- 未登录访问 `/` 与 `/api/*` 分别重定向/401。
- 登录成功后能读到自己的账目；读不到他人的。
- 用他人 id 调 `/api/confirm` 返回 404。
- 管理员在「全部账本」下能读到所有用户的数据；普通用户传 `scope=all` 无效（仍只返回自己的）。
- 禁用用户后其会话立即失效。
- 不能降级/禁用最后一个管理员。
- 连续失败登录达到阈值后被限流。

## 范围外

- 用户自助注册、找回密码、邮箱验证。
- 第三方登录（OAuth）。
- 审计日志的完整留痕（仅记录登录失败）。
- 多租户共享账本（多人共同编辑同一本账）。
- 每个用户独立数据库文件（本轮采用单库 + `owner_id`）。
- 历史数据迁移（明确清空重建）。
- 移动端原生 App 或小程序。
- 数据导入的跨用户去重。

## 补充说明

- **Cloudflare Tunnel 需外部前置条件**：一个托管在 Cloudflare 的域名。在域名就位前，代码、Dockerfile、compose 与配置模板可以完成，`cloudflared` 的 `TUNNEL_TOKEN` 由用户填写。
- **清空重建是用户明确选择**，不可逆；本规格不含备份步骤。
- **PWA 必须 HTTPS**：证书缺失时浏览器不会注册 service worker，因此 PWA 与 Tunnel 是绑定的，不能只做前者。
- **管理员也是用户**：管理员有自己的账本，默认视图是自己的数据，「全部账本」是显式切换的状态，且不持久化（刷新回到自己的账本）。
