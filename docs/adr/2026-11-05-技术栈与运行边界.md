# 2026-11-05 技术栈与运行边界

## 背景

要做的是一个把微信/支付宝导出账单变成月度结论的本地工具。样本为微信与支付宝的个人导出账单，含姓名、账户、流水号等个人信息（真实样本不入库）。本机硬件为 16 GB 内存、MX250 2 GB 显存、无独立推理卡。

## 选项

| 维度 | 选项 | 结论 |
|---|---|---|
| 产品形态 | 本地 Web / 桌面客户端 / CLI / 纯 MCP | 本地 Web：图表与筛选有地方放，且无需打包与账号体系 |
| 部署边界 | 仅 localhost / 局域网 / 公网 | 仅 localhost：无鉴权需求，PII 不出机 |
| 后端框架 | Hono / Fastify / Next.js / Bun+Elysia | Hono：单进程、无打包魔法、原生模块无冲突 |
| 前端 | Vite + React / Next 一体化 | Vite + React：本地工具用不上 SSR/RSC |
| 数据库 | `node:sqlite` / `better-sqlite3` | `node:sqlite`：Node 25 内置，实测可用，免原生编译 |
| 模型 | 云端 LLM / 本地 MiniCPM-V 4.7 1B / 35B-A3B | 本地 1B：数据不出机；35B-A3B 在本机不可用（Q4 权重约 20 GB） |
| 推理运行时 | llama.cpp / Ollama / transformers | llama.cpp：官方已支持 4.7，单二进制，OpenAI 兼容 |
| 分类策略 | 规则优先 + 模型兜底 / 全量模型 | 规则优先：小模型中文商户分类准确率不足，错误需集中在可修处 |

## 决定

1. 技术栈：Node 25 + TypeScript，Hono 提供 HTTP 与静态托管，Vite + React 提供前端，`node:sqlite` 存储。
2. 仅监听 `127.0.0.1`，无鉴权、无多用户、无公网入口。
3. 分类走「规则优先、本地 1B 兜底」，模型经 `llama-server` 的 OpenAI 兼容接口调用，输出受 JSON schema 约束。
4. 真实账单只存放于 `data/`（gitignored），仓库内仅允许脱敏或合成样本。
5. 金额以整数分存储。

## 后果

- 放弃 SSR/SEO/公网部署能力；若将来要多设备访问，需要重新评估框架（届时 Next.js 会变合理）。
- 模型质量受 1.55B 参数限制，分类准确性主要由规则库承担；规则库成为需要持续维护的资产。
- `node:sqlite` 在 Node 25 仍标记为 experimental：升级 Node 主版本前必须回归导入与迁移用例。
- 依赖本机 GPU/CPU 算力，分类批处理的吞吐远低于云模型，故导入与分类必须解耦为可重入的批处理。
